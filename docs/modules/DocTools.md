# DocTools

**Path:** `tools/DocTools/` · **Kind:** .NET project (console, net10.0) · **References:** `CityBuilder.Api`, `CityBuilder.Infrastructure`,
`CityBuilder.Simulation` · **Referenced by:** `DocTools.Tests`

## Purpose
DocTools writes the reference pages in `docs/reference/generated/` from the code and the content, and checks in CI that the committed
pages are current (`core-instructions/17-documentation-system.md` §3). The pages show the system as built. The normative specs stay in
`core-instructions/` (`05`, `06`, `23`). DocTools never changes code or content, and nobody edits its pages by hand.

| Command | What it does |
|---|---|
| `dotnet run --project tools/DocTools -- generate` | Rewrites every page and deletes pages no generator makes any more |
| `dotnet run --project tools/DocTools -- check` | Regenerates into a temporary folder and compares. Exit 1 lists each changed, missing or extra page, with its first differing line (CI step "Generated docs are current") |

Both commands accept `--root` and a folder (the repository root). By default the tool uses the first folder above it that holds `global.json`.

| Page | Made by | From |
|---|---|---|
| `configuration.md` | `ConfigurationPage` | the API's options classes (public, with a `SectionName` constant), their defaults and doc comments (`XmlDocs`, the API's XML doc file), `appsettings*.json` |
| `content.md` | `ContentPage` | every `server/content/*.json` through `ContentFileLoader`; per-hour rates from the engine's `ProductionDisplay.PerHour` |
| `db-schema.md` | `DbSchemaPage` | the design-time EF Core model of `CityBuilderDbContext` (no connection) and its migrations |
| `endpoints.md` | `EndpointsPage` | the OpenAPI document the API's build writes, `server/src/CityBuilder.Api/obj/openapi/CityBuilder.Api.json` (`OpenApi/BuildTimeDocument` in the API) |
| `errors.md` | `ErrorsPage` | `ErrorCatalogue.All` |
| `project-map.md` | `ProjectMapPage` | the `.csproj` files under `server/`, `shared/`, `tools/`; the project's `.asmdef` files |

## Key types
| Type | Responsibility |
|---|---|
| `CommandLine` | The two commands and their exit codes (0 current, 1 out of date, 2 usage) |
| `ReferenceDocs` | The list of generators; writes the set of pages into a folder |
| `MarkdownPage` | Builds one page: the "Generated by tools/DocTools — do not edit" line, the title, tables, Mermaid, escaping |
| `GeneratedDocsCheck` | Compares committed and fresh pages (`PageDifference`) and runs the `check` command |
| `RepositoryFiles`, `RepositoryRoot` | Find the repository's own files in ordinal order, and the root |
| `XmlDocs` | Reads a project's XML doc file; a reference to a constant shows its value |
| `Pages/*Page` | One generator per page |

## Rules and invariants
- **Deterministic:** the same repository gives the same bytes on every machine. Lines end in `\n`, files are UTF-8 without a BOM,
  everything is sorted ordinally or kept in its source order, and pages hold no timestamps and no absolute paths.
- Every page starts with the line `MarkdownPage.Notice` and is plain CommonMark for the handbook (`17` §7). `MarkdownPage.Text`
  escapes pipes and angle brackets.

## How to extend
A new page is a new `Pages/<Name>Page.cs` with a `Generate(root)` method, plus one entry in `ReferenceDocs.Generate`. Run `generate`,
commit the page, and add a row to the page table above. A change to code or content that a page shows: run `generate` and commit
the changed pages in the same PR (recipes in `core-instructions/19-change-recipes.md`).

## Tests
`tools/DocTools.Tests` is in the server's solution, so the fast suite runs it:
`dotnet test server/CityBuilder.slnx --filter "Category!=Integration"`. It checks that two runs give identical bytes; that every page
starts with the notice; that the check reports a modified, a missing and an extra page; that the usage errors work; and that the
committed pages are current.

## Known limitations
- The pages are only as complete as the generators. A fact no generator reads (for example a rule inside a validation lambda) is
  in the generated page only if a doc comment states it.
- `endpoints.md` needs the API built first (the build writes the document); `dotnet run` builds it. `/health` is not in the document.
- A research effect type `ContentPage.Effect` doesn't know stops the generation, on purpose, until it gets a sentence.
- The browser tab of a generated page shows its file name: Docusaurus takes the tab title only from an H1 at the very top, and the
  notice comes first (build log M0-61, decision 5). The sidebar label is the H1.
