# Configuration reference

Source: the options classes of `server/src/CityBuilder.Api/` and its `appsettings.json` and `appsettings.Development.json`. The normative specs stay in `core-instructions/`; this page shows the code as built.

Any key can be set with an environment variable (`:` becomes `__`, for example `Auth__SigningKey`) or a command-line argument (`-- --Key=value` after `dotnet run`). A blank cell means the file doesn't set the key. Secrets (the connection string, the signing key) come from user-secrets or the environment, never a committed file (`docs/getting-started.md` → Database).

| Key | Type | Default | appsettings.json | Development | Meaning and validation |
|---|---|---|---|---|---|
| `Auth:SigningKey` | `string` | (empty) |  |  | The secret the access tokens are signed and checked with (HMAC-SHA256), at least 32 bytes as UTF-8, required in every environment. Anyone who knows it can sign a token for any player, so it comes from user-secrets or the environment variable `Auth__SigningKey`, never from a committed file. |
| `Auth:TokenLifetimeMinutes` | `int` | `720` |  |  | How long an access token is valid after it was issued. Default 720 (12 hours); between 1 and 1440, or the start stops. |
| `Auth:DevLoginEnabled` | `bool` | `false` | `false` | `true` | Map `POST /api/v1/auth/dev-login`, which logs anyone in by name alone. Only allowed in Development (`true` in `appsettings.Development.json`, `false` in `appsettings.json`); `true` in any other environment stops the start. |
| `Content:FilePath` | `string` | (empty) | `content/mvp-content.json` |  | Required: the content file, absolute or relative to the app's base directory (where the build copies `server/content/*.json` into `content/`). The default in `appsettings.json` is `content/mvp-content.json`. |
| `ConnectionStrings:CityBuilder` | `string` | (empty) |  |  | The PostgreSQL connection string, from `ConnectionStrings:CityBuilder`, required. It holds a password, so it comes from user-secrets or the environment variable `ConnectionStrings__CityBuilder`, never from a committed file. |
| `Database:ApplyMigrationsAtStartup` | `bool` | `false` | `false` | `true` | Apply the pending migrations before the server accepts requests. Only allowed in Development (`true` in `appsettings.Development.json`, `false` in `appsettings.json`); `true` in any other environment stops the start, because there the migrations are applied on purpose, never as a side effect. |
| `Database:LockTimeoutMilliseconds` | `int` | `3000` |  |  | How long a request waits for its city's row lock (PostgreSQL's `lock_timeout`) before it fails with `CONCURRENCY_CONFLICT` and the client retries (core-instructions/06-data-model.md: about 3 s). Default 3000; between 1 and 60000, or the start stops. |
| `RateLimits:Commands:Burst:Limit` | `int` | `10` |  |  | Every command endpoint, counted together per player. A short window that allows a quick run of taps. Default 10 per second. The most requests one player (or address) may make in one window: 1 to 1000000, or the start stops. |
| `RateLimits:Commands:Burst:WindowSeconds` | `int` | `1` |  |  | Every command endpoint, counted together per player. A short window that allows a quick run of taps. Default 10 per second. The window's length in seconds: 1 to 3600, or the start stops. |
| `RateLimits:Commands:Sustained:Limit` | `int` | `120` |  |  | Every command endpoint, counted together per player. A long window that stops a script. Default 120 per minute. The most requests one player (or address) may make in one window: 1 to 1000000, or the start stops. |
| `RateLimits:Commands:Sustained:WindowSeconds` | `int` | `60` |  |  | Every command endpoint, counted together per player. A long window that stops a script. Default 120 per minute. The window's length in seconds: 1 to 3600, or the start stops. |
| `RateLimits:City:Limit` | `int` | `30` |  |  | `GET /city` per player. Default 30 per minute. The most requests one player (or address) may make in one window: 1 to 1000000, or the start stops. |
| `RateLimits:City:WindowSeconds` | `int` | `60` |  |  | `GET /city` per player. Default 30 per minute. The window's length in seconds: 1 to 3600, or the start stops. |
| `RateLimits:Content:Limit` | `int` | `30` |  |  | `GET /content` per player, a budget apart from the city's. Default 30 per minute. The most requests one player (or address) may make in one window: 1 to 1000000, or the start stops. |
| `RateLimits:Content:WindowSeconds` | `int` | `60` |  |  | `GET /content` per player, a budget apart from the city's. Default 30 per minute. The window's length in seconds: 1 to 3600, or the start stops. |
| `RateLimits:DevLogin:Limit` | `int` | `10` |  |  | The dev login per remote address. Default 10 per minute. The most requests one player (or address) may make in one window: 1 to 1000000, or the start stops. |
| `RateLimits:DevLogin:WindowSeconds` | `int` | `60` |  |  | The dev login per remote address. Default 10 per minute. The window's length in seconds: 1 to 3600, or the start stops. |
| `RequestLimits:MaxBodyBytes` | `int` | `4096` |  |  | The largest request body the server reads, in bytes. A body of the contract is a few hundred bytes; a larger one is refused before anything reads or runs it (`RequestBodyLimit`). Default 4096; between 1024 and 1048576, or the start stops. |
| `Simulation:DevTimeScale` | `int` | `1` |  | `1` | How many seconds of server time pass per real second on a Development server (60 = one hour per minute), for playing a long scenario by hand. Default 1 (real time); between 1 and 1000, and exactly 1 outside Development, or the start stops. The engine never sees it: the server clock does. |
| `Simulation:PresenceGraceSeconds` | `long` | `300` |  |  | How long, in real seconds, the player still counts as present after a request (`04` section 2): couriers spend stamina only after it. Default 300 (five minutes); 0 to 86400. The settle uses it times the clock's scale (`AddServerClock`), so it stays real time on a fast clock. |
