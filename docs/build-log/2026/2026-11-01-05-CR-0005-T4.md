## Decisions
<!-- Every decision, when it is made, including small ones. Scope: local | project-wide (→ 12-decisions.md row) | architectural (→ ADR). -->
| # | Decision | Alternatives considered | Why | Scope |
|---|---|---|---|---|
| 1 | The icons move from `art/ui/icons/` to `Assets/_Project/Resources/UI/Icons/` and `render_ui.py` writes them there | Copying them (two copies to keep equal); an `Art/Resources/Icons` folder | The owner chose one copy for the models (CR-0005 Risks); the same reasoning holds for the icons. `Resources/UI/` is where decision 024 puts what code loads by name; nothing else in `art/ui/` reads `icons/` | local |
| 2 | The HUD's chip icon keeps the first-letter label as the fallback for an item with no picture; the workers, builders, research and card pictures are hidden when their file is missing | Failing loudly in the view | `UiIconsTests` already fails when a content id has no icon, so a player never sees the fallback with the real content; the fallback only keeps a build with a stale art folder usable | local |
| 3 | Workers and builders keep their text captions and get the picture beside the value; the research ring keeps its name and time and gets the picture in its middle | Replacing the captions with pictures | The captions are the only text that says what a number is, for a player who does not know the picture; the owner can drop them after a look | local |
| 4 | `UiIcons.Show` removes the inline background with `StyleKeyword.Null` (Unity reads `None` back as `Null`), and compares the inline style, not the resolved one, which lags until layout | Comparing `resolvedStyle` | The first test run failed on `None`; the inline value is what this code wrote | local |
| 5 | The cards' pictures are set once when the card is made; item chips are set at every refresh but `Show` writes only when the picture differs | Setting both at every refresh | A card's type never changes; chips are rewritten in place and may change item order only when the count differs | local |
