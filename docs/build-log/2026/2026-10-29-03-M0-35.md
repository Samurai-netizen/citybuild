- **Start:** PR #46 (M0-34) is merged (`bdedcb1`); the branch starts from that `main`, and M0-34's board row goes to `Done` with this task.
  Model: Opus 5.5, set by the owner with `/model` before `/start-task` (the task is `[S]`, which names Sonnet 5.5). No agents (OD-9).
  Not `[PLAN]`: no approval gate; decisions are logged as they are made.
- **What exists** (read first): JSON console logs with scopes (M0-02 decision 9); three source-generated log classes (`ContentLog` 1000,
  `DatabaseLog` 2000, `ErrorLog` 3000, decision 029); no log for auth, commands, settlements or rate limits; `GET /content` reports the
  constant `timeScale` 1; `TimeProvider.System` is the server clock; Application has no logging package (M0-23 decision 7), so logs are
  written in the Api from what the use cases return. Open from earlier tasks: the clock-behind warning of `04` §1 (M0-28 decision 14);
  lock timeouts and `CONCURRENCY_CONFLICT` in the logs (ADR-0009, M0-24); `docs/api/` in the docs layout (M0-01 audit A11).
- **Plan:**
  1. **Dev time scale:** `Api/Time/`: `SimulationOptions` (`Simulation:DevTimeScale`, default 1, validated on start: in range, and 1 outside
     Development), `ScaledTimeProvider` (now = origin + (real now − origin) × scale, from a fixed origin so the clock is continuous across
     restarts), the registration (`TimeProvider` is the scaled one only in Development with a scale above 1), the active scale as
     `rules.timeScale` in `GET /content`, a startup warning when it runs. Tests: the provider's arithmetic, the guard (start stops), `timeScale`
     1 in Production and the active value in Development. Docs: getting-started (key, reset the dev database), `05`, `04` §1, `07`, module doc.
  2. **Auth, rate-limit and error logs:** `AuthLog` (dev login success, a refused token with the kind of failure, never the token),
     rate-limit hits (class, player; never an address), a concurrency conflict outside a command (the handler). Correlation: check that every
     line carries the trace id of the answer. Tests with a capturing logger: event ids, values, no token or body in any line.
  3. **Command and settlement logs:** command accepted / rejected (code) / replayed / concurrency conflict with player, request id, command and
     duration; settlement (elapsed, production seconds, events, research completed, saved, duration) for `GET /city` and every command that
     settled; the clock-behind warning. `CommandResult` carries the settlement of a command that settled. Tests over HTTP (fake store and
     PostgreSQL).
  4. **Docs:** `docs/api/` (traceId vs requestId, the log events), its place in `03`, `docs/README.md` and the handbook; `07` logging policy;
     module docs; ADR-0005/0009 As built; decision row(s).
  5. **Finish:** Definition of Done, self-review, the real server by hand as `devtest` (OD-14), PR.
