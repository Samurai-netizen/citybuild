- `SeededRandom` starts seed n at n × the SplitMix64 step, which is seed 0's state after n draws, so each seed's numbers are seed 0's
  sequence from its (n + 1)th number on. The histories still differ, because each draw feeds a different decision, but nearby seeds are
  not independent. Mixing the seed once would fix it; it changes every property history and the reference test, so it needs its own task
  or CR (the owner's call). Its doc comment now says how seeding works.
