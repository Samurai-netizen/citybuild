## Sessions

### Session 1 — 2026-11-02 · Claude Code / claude-opus-5-5
- **Start:** M0-59 merged (PR #84, squash). The session branch still held M0-59's commits; `origin/main` merged into it (Owner input 1).
  Hooks enabled. The container has the .NET SDK, no Unity.
- **Review so far (read before planning):** the client sends only intent and a `requestId` in its four command bodies, a dev name in the dev
  login, and the headers `Accept`, `Content-Type`, `Authorization` and `X-Client-Version`; the server binds only the contract types, the player
  only from the token, and the version only into a log scope (M0-58). Gaps found:
  1. `ApiClient` takes an `http://` base URL in any build. Unity's "Allow downloads over HTTP: development builds" setting would throw from
     `UnityWebRequest` in a release build, as an exception, not a result, and no test pins that setting.
  2. ASP.NET Core takes the request's trace id from the client's `traceparent` header (and reads `baggage`), so a client chooses the trace id
     the server logs and answers with.
  3. No single test lists what each endpoint reads from a request; a later endpoint could bind a query or header value unnoticed.
- **Plan:**
  1. Client: HTTP only in development builds. `ApiClient` refuses `http://` unless the caller allows it (`allowInsecureHttp`, default off);
     `GameRoot` allows it for `Debug.isDebugBuild`; a release build with an http address shows the bad-settings screen. Tests, plus an
     EditMode test that pins the Player setting `insecureHttpOption` to development builds.
  2. Server: the trace id is always the server's own: a propagator that reads no trace context or baggage from the request. `Security_` test.
  3. Server: one inventory test over every endpoint: what it binds from the request (body properties, route, query, header) equals the list
     in `07`; nothing else.
  4. `07`: a "What the client sends" inventory (fields and headers), the HTTP rule, token storage and logging checked; `09`,
     `logs-and-correlation.md`, module docs, `CHANGELOG`.
- **Done:** step 1 (`ApiClient` `allowInsecureHttp`, `GameRoot`, `ApiClientTests` +3, `InsecureHttpSettingTests`, 24 test call sites opt in).
  Compiled only `ApiClient` and the rest of `Net` without Unity types (scratch project, .NET 10, stubs for `AppInfo` and `ClientLog`): builds.
  Step 2 (`ServerTraceContext`, registered in `Program.cs`; `RequestLogTests.Security_TraceContextFromTheClient_IsIgnored`, failed first:
  the answer's `traceId` held the client's trace id). Step 3 (`ClientInputInventoryTests`, 2 tests; a mutation check, an `int? coins`
  parameter on `GET /city`, failed it with `Query:coins`, then reverted).
