| # | Decision | Alternatives considered | Why | Scope |
|---|---|---|---|---|
| 2 | The script is psql with `\gset`/`\if`, not a PL/pgSQL function or an app tool | A .NET tool in `tools/`; a function installed in the database | Nothing is installed in the database and no new project or dependency (G-Dependency); the file is run by the panel and by the test unchanged | local |
| 3 | The script runs inside the compose container (`docker compose exec postgres`) and the test inside the Testcontainers container | Host `psql` | No client install is needed on either side, and the dev database is only ever the local container | local |
| 4 | A refusal prints `REFUSED: …` and exits 0 from psql; `panel.sh` turns that into a non-zero exit | Making psql fail | psql has no clean way to set an exit code from a script; the wrapper owns the exit code | local |
| 5 | A remove from an empty stock, or a set to the same number, writes no ledger row (the state version still goes up by one) | A zero-delta ledger row | A ledger row with delta 0 says nothing | local |
| 6 | The item list needs `python3` (read from the content JSON) | `jq`, or a hand-kept list in the script | `python3` ships with macOS's developer tools, `jq` does not; a hand list would break rule 8 | local |
| 7 | `panel.sh`'s menu and CLI both end in the same `goods` function | Two code paths | One validation, one call into the database | local |
| 8 | `test-goods.sh` is not wired into CI | Editing `.github/workflows/ci.yml` | Workflow files are protected (`15`); the shell script is a developer tool. Offered as a follow-up | local |
