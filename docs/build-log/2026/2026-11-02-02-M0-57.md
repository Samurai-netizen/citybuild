## Sessions

### Session 1 — 2026-11-02 · Claude Code / claude-sonnet-5-5
- **Plan:**
  1. `CityBuilder.Client.Core`: `LogLevel`, `ILogSink`, `UnityLogSink` (over `UnityEngine.Debug`), `ClientLog` (static entry point: `Debug`,
     `Info`, `Warning`, `Error`, `Exception`; the level defaults by build type: Debug in the Editor and development builds, Warning in
     release). EditMode tests with a recording sink: level filtering, the build-type default, formatting.
  2. `CityBuilder.Client.Net`: `ApiClient` logs each request at Debug (method, path, status, milliseconds; never a body or a token) and
     each failed request at Warning with the error code, status and `traceId` (`ApiError.ToString()` already carries it). Tests with a
     fake transport: the Debug line has no token and no body; the Warning line has the trace id.
  3. Replace the existing `Debug.Log*` calls in `Net`, `Core` and `Presentation` with `ClientLog` (the Editor script keeps its own: editor
     only). `CommandFeedback`'s warning for a failed command gets the trace id of the error.
  4. A guard test: no runtime source under `Assets/_Project` (except the Unity sink) calls `UnityEngine.Debug.Log*` directly.
  5. Docs (Docs impact below), `CHANGELOG`, finish.

## Decisions

| # | Decision | Alternatives considered | Why | Scope |
|---|---|---|---|---|
| 1 | The logger lives in `CityBuilder.Client.Core` | A new assembly; `Net` | `Core`, `Net` and `Presentation` all log and all may reference `Core` (`03`), so no new project or dependency is needed | local |
