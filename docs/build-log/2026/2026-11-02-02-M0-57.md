## Decisions
<!-- Every decision, when it is made, including small ones. Scope: local | project-wide (→ 12-decisions.md row) | architectural (→ ADR). -->
| # | Decision | Alternatives considered | Why | Scope |
|---|---|---|---|---|
| 1 | The logger lives in `CityBuilder.Client.Core` | A new assembly; `Net` | `Core`, `Net` and `Presentation` all log and all may reference `Core` (`03`), so no new project or dependency is needed | local |
| 2 | No log line carries a request or response body or a token, in any build; the level only decides how many lines there are | Bodies at Debug in development builds | The rule "never log tokens or full responses in release builds" is then true by construction, not by a build flag; `ApiError.Detail` is a short sentence, not a body | local |
| 3 | `ClientLogger` is an immutable instance (level and sink fixed by its constructor); `ClientLog` holds `static readonly Default` (build-type level over `UnityLogSink`) and forwarding methods, nothing settable. `ApiClient` and `CommandFeedback` take an optional `ClientLogger`, so their tests pass a recording sink (owner chose B, see Owner input) | A static class with a settable level and sink (it broke "no static mutable state"); an instance in every class | Keeps the rule of `14`, `09` and `unity.md` as written, needs no exception, and still lets tests see what is logged; the other ~30 call sites stay one-liners through `ClientLog` | local |
| 4 | `UnityLogSink` writes an exception only with `Debug.LogException` (not also `LogError`); a Debug line has the prefix `[debug] ` | Two lines per exception; no prefix | `LogException` already prints message and stack trace; Unity has no level below "log", so the prefix keeps Debug lines apart from Info on a device | local |
| 5 | `ApiClient` writes one line per request: Debug when it worked, Warning (not also Debug) when it failed. It names method, path (no base URL), status, milliseconds (`Stopwatch`) and, for a failure, `ApiError.ToString()` (code, status, detail, trace id) | A Debug line for every request plus a Warning for failures; the request id in the line | One line per request is easy to match to the server log by trace id; a failure must show in a release build, so it is a Warning; the request id is in the command body, which is never logged | local |

## Problems and surprises
- (Resolved by B.) `ClientLog` broke "no static mutable state" (`14`, `09`, `.claude/rules/unity.md`): `Level` and `Sink` are settable statics, which is what lets tests swap the sink. Options put to the owner: **A** keep it and write one named exception into those three places; **B** (recommended) an immutable `ClientLogger` instance (level and sink fixed by its constructor) held in a `static readonly ClientLog.Default`, with `ApiClient` and `CommandFeedback` taking an optional logger so their tests inject a recording sink; no rule changes; **C** no sink or level override at all, tests use `LogAssert`.
