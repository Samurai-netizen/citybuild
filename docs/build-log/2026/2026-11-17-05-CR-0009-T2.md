  `MetricsData`, `CheckpointMatcher`, `PlayerTimeline`. D. explorer (rows and details). E. funnels, actions, friction, return, one player.
  F. `MetricsLoader` (read-only transaction) and the PostgreSQL tests. G. `HtmlReport`. H. `panel.sh metrics`, `test-metrics.sh`.
  I. a real run on the dev database, then the docs and the finish.
- **Test list, part A:** `--out` is required; the defaults (checkpoint and content file from the repository root, left after 3 days,
  min sample 5, no period, no exclude, no player); each option parsed; `--exclude a,b` splits and trims; an unknown option, a missing
  value, a bad date, a `--to` before `--from`, a non-positive number and a bad `--player` uuid each give exit code 1 with a message on
  stderr and write nothing; `--help` prints the usage with exit code 0; the new projects satisfy `ProjectFileTests` (header comment).
- **Done:** A. `tools/MetricsReport` and `MetricsReport.Tests` in the solution; `CommandLine` (options, defaults, exit codes 0/1/2, usage),
  `RepositoryRoot`; 14 tests. Docs: `03`, overview, module doc, modules index, `tools/README.md`, project map regenerated.
- **Test list, part B:** a valid file gives its checkpoints (fields, `atLeast` default 1) and funnels; `{}` and empty lists are valid;
  each error names its line: malformed JSON, an unknown field, a missing `id`/`title`/`event`, a bad id, a duplicate id, an unknown
  event type, a `detail` not in the content, `atLeast` below 1, a funnel step that names no checkpoint or appears twice; the committed
  `checkpoints.json` is valid against the committed content.
- **Done:** B. `CheckpointFile` (strict `Utf8JsonReader` parse, every error with its line), `Checkpoint`, `Funnel`, `KnownEvents`,
  `CheckpointFileException`; the starter `server/analytics/checkpoints.json` built from the content ids (21 checkpoints, funnel
  "First session"); 25 new tests, 39 in the tool. Docs: module doc.
- **Test list, part C:** a match needs the same event type, and `detail`, `outcome` equal only when the checkpoint names them, and
  `value >= minValue` when it names one; reached = `atLeast` matches, the reach is the `atLeast`-th in `(created_at, id)` order
  (a tie on time: the lower id first); fewer matches: not reached; every distinct `(event_type, detail, outcome)` becomes an unnamed
  checkpoint with the title `event_type / detail / outcome`; a player's timeline is in `(created_at, id)` order with the reach of each
  checkpoint; no events: nothing reached.
- **Done:** C. `MetricsData` (players, events: plain records), `ReportCheckpoint` (named or unnamed), `CheckpointMatcher` (match
  rules, unnamed triples, all checkpoints), `PlayerTimeline` (order, reach, count); `TestData` builder for the tests; 9 new tests, 48
  in the tool. Docs: module doc.
- **Test list, part D:** on a hand-made data set with known answers: reached (players, %), times in total and median per player,
  median real time and city clock to the reach, left after / without / difference, last stop (named and unnamed apart; a tie: the
  higher event id), median time and sessions after the reach; a checkpoint nobody reached and one everybody reached (`—`, no division
  by zero); nobody left, everybody left; the small-sample mark; "now" is the later of the clock and the newest last seen; percentages
  rounded half up, the lower median; a checkpoint in no funnel has the same numbers as in one; details: top five next events, top five
  last events of those who left after it, the other named checkpoints they reached.
- **Done:** D. `ReportContext` (timelines, "now", left, least sample), `Explorer` (rows with every column of §3.4, last stop named and
  unnamed apart, default order, detail blocks for named rows and the 50 most reached unnamed), `Rate` (tenths from counts, `—`, small
  mark), `Stats` (lower median, rounding); `PlayerTimeline.ReachIndex`; 23 new tests, 71 in the tool. Docs: module doc.
- **Test list, part E:** funnels: reached per step in order (a player who reached step 3 before step 2 is not counted at step 3), % of
  population and of the step before, the drop, median time from the step before, a funnel nobody enters; actions per `event_type`:
  players (count, %), times, median per player; friction per command and error code: players hit (count, %), times; the last event of
  each leaver grouped, top ten; leavers whose last session (from their last `session.start`) held a refusal, by command and code;
  return per creation day (UTC): players and % with a `session.start` on day 1, 3, 7, `—` for a cohort too young; one player: the
  timeline rows in order, at most 5000, an unknown id gives none.
- **Done:** E. `Funnels` (steps in order, shares of the population and of the step before, drop, median time), `Actions` (per event
  type), `Friction` (refusals by command and code, the leavers' last events top ten, refusals in their last session), `Returns` (day
  1/3/7 per creation day, `—` while the day runs), `OnePlayer` (at most 5000 rows); 19 new tests, 90 in the tool. Docs: module doc.
- **Test list, part F:** on PostgreSQL with seeded players and known answers: players and events load as `MetricsData`; the period
  (`--from`, `--to`) and `--exclude` remove players, no name is read; `production.first` comes from the first ledger row per city and
  item; left after, left without and last stop match the unit answers; the transaction is read-only (a write inside it fails); a
  database without `player_events` gives exit code 2.
- **Stopped at / next:** part F (`MetricsLoader`, the PostgreSQL tests).

| 11 | Actions per `event_type` only (the plan); friction sorts by players, then times; a leaver with no events is not in "last events" (its shares stay of all who left); return counts a `session.start` on exactly UTC day N, `—` until day N has ended at "now"; the class is `Returns` (CA1716 forbids `Return`) | "by day N"; partial days | the triples are already in the explorer; a running day would understate the share | local |
