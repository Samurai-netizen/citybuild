| 1 | Item names are the content's, as they are: `2 Logs → 1 Planks`, not the spec's `1 Plank` | Strip a trailing "s" when the quantity is 1; add a singular name to the content | The content has one (plural) name per item; guessing English plurals breaks on other words, and a content field is a contract change that needs the owner (`15`) | local; follow-up |
| 2 | The recipe rate is `ProductionDisplay.PerHour` on a throwaway level 1 `Building` with 0 workers, asked for the level's most workers | Repeat `CeilDiv(EffectiveLabor, workers)` in the client; add a type-based helper to the engine | One source for rates (the card equals the inspector and the simulator, research included) with no engine change and no copied formula | local |
| 3 | A producer with no input reads `Nothing → 1 Logs · 120/h at 2 workers`; a house (no recipe) reads `Provides 4 workers` and has no "Max workers" line; several outputs show `rate Item` each | `→ 1 Logs`; hide the recipe line of a house | The arrow always has a left side; a house still tells the player what it is for | local |
| 4 | The hint order is the server's (`PlaceBuilding`: builder, then cost): `All builders are busy`, else `Not enough <items short>`; a locked card shows the lock and no hint | Show both hints; hint on locked cards too | One line per card; a price warning on a card the player cannot build is noise; it mirrors the error the server would answer | local |
| 5 | Lock text: `Requires: <research name>`; a type of a later era than the city's reads `Requires: <era name>`; the test is `CityQueries.IsUnlocked` (the server's rule) | Own checks in the client | The shared rule cannot drift from the server | local |
| 6 | `BuildMenuModel.TryToggle` selects a card, a second tap on it deselects; a locked or unknown card changes nothing; an unaffordable card can be selected; `Update` deselects a type that became locked | Select only; refuse unaffordable cards | `09`: hints never block, the server decides; the toggle gives the placement flow (M0-46) a cancel at once | local |
| 7 | `DurationText` shows every non-zero unit (`1h 1m 5s`), hours are the largest unit | Drop seconds above one minute | Matches the spec's `2m 30s`; no M0 content takes days | local |
| 8 | The cards are judged by `DisplayCity.Current` (the latest snapshot advanced to now), not by the raw snapshot | `ClientCityStore.CopyCity()` of the snapshot (the spec's words "from the latest snapshot") | The display city *is* the latest snapshot plus the engine's prediction of production; the raw snapshot can be 120 s old and would warn "not enough Logs" for stock that has arrived. Still a hint only, and no resource is subtracted (`09` UX rules) | local |
| 9 | The menu is its own `UIDocument` on a child object `Build Menu` (sort order 1, the shared `PanelSettings`); `Create` makes it and its cards are built in `Start`, when the tree exists | Swap the one document's layout like the fatal screen does; build in `Create` | The status label stays up beside it; `Start` is the point where the tree is known to exist (as `GameRoot.Start` relies on) | local |
| 10 | A locked card is disabled (`SetEnabled(false)`) and gets `build-card--locked` (half opacity); the model refuses it too | Class only | A disabled element gets no pointer events, and the model is the rule if some other caller taps | local |
| 11 | `CityInputReader` takes an optional `isOverUi` predicate and `CityWorld.IsPointerOverUi` supplies it (`GameRoot` sets it to `BuildMenu.IsOverUi`, which asks the panel's `Pick`): a press that starts over the UI never pans, taps or hovers the ground, even when it moves off the UI; the wheel over the UI does not zoom. Six PlayMode reader tests | Leave it (M0-43 decision 15 deferred "UI overlap") | Without it a tap on a card also selects the tile under the card, which the placement flow (M0-46) would turn into a placement. A small change in M0-43's classes, needed for this screen; reported to the owner | local |
| 12 | The build UI pads its root by `Screen.safeArea` (`SafeAreaInsets.From`, pure maths in `Presentation/Ui/`, tested) on top of 16 | Ignore the safe area | `09` UX rules; later screens reuse it | local |
| 13 | Picking a card does not close the sheet and closing the sheet does not clear the pick; the "Build" button reads "Close" while open | Close on pick | M0-46 owns what the placement flow does with the pick and the sheet; the menu keeps both states independent and simple | local |
| 14 | Unity ran in a mirror project again (the owner's Editor holds the lock): `scratchpad/run-unity.sh` rsyncs `Assets`, `Packages` and `ProjectSettings` into a `cp -Rc` copy beside a `shared` symlink; the `.meta` files the Editor had not written were copied back | Ask the owner to close the Editor | Same reason as M0-44 decision 8 | local |
| 15 | `ScreenPoint.ToTopLeft` is the one flip between the Input System's bottom-left pixels and a panel's top-left space (`RuntimePanelUtils.ScreenToPanel` scales but does not flip: printed in a PlayMode run) | Flip inline in `BuildMenu.IsOverUi` | The flip is the easy thing to get wrong and the scene test cannot pin it alone (see Finish), so it is a pure function with its own test | local |
