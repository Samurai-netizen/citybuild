| 1 | **Split (owner):** M0-07 becomes M0-07a (engine content model and validation: spec items 1 and 2, the failing case per rule of item 5, the engine module doc of item 6) and M0-07b (items 3 and 4, the real file test of item 5, the how-to and the server module docs of item 6). Each part has its own board row, build log entry and PR. A letter after the two digits marks a split plan task: the id pattern in `.githooks/commit-msg` and `.github/workflows/ci.yml` becomes `M[0-9]+-[0-9]{2}[a-z]?` (both protected, approved by the owner) and `18` says so | One PR (~3.5–4.5k lines); M0-07 + a new M0-85 (no protected edits) | The owner's choice in both questions (Owner input). The size is far above the ~600 lines of `14`, and the seam between the engine and the server is clean: M0-08 needs only the engine part | project-wide (plan board, `13` → Deviations, `18`) |
| 2 | **Two layers in the engine:** `*Data` classes in `CityBuilder.Simulation.Content.Data` mirror the JSON (settable properties, every value optional, no checks). `GameContentFactory.Create(GameContentData)` returns a `GameContentResult`: the `GameContent` or every `ContentError` (code, path, message), never an exception for bad data. The definitions are immutable and only the factory constructs them (internal constructors) | The server loader builds the definitions directly (fewer types, but shape checks such as missing fields would live in the loader and be written again for the client's `GET /content`); JSON fixture files per rule (each a full copy of the content) | One place checks everything, missing values included, on the server and on the client alike (Newtonsoft can fill the same `*Data` classes). A test changes one value of a valid in-code sample per rule | project-wide (→ `12` row) |
| 3 | **Ids (row 022 left this to this plan):** `BuildingTypeId` and `ResearchId` are copies of `ItemId` (ordinal equality and order). `EraId` (`early_medieval`) has equality only: no `IComparable`, no relational operators. Items, buildings, research and the starting city name their era by **number** (`"era": 1`, as in the snapshot of `05`), so era order is the number's order. The factory checks every id's text: a lowercase letter first, then lowercase letters, digits or `_`, at most 64 characters | One generic `ContentId<TTag>` (a second pattern next to `ItemId`); eras referenced by `EraId` and ordered by a lookup | Matches `ItemId` and row 022 (an id with a numeric order is ordered by the number). Typed ids stop a research id where a building id belongs | project-wide (→ `12` row) |
| 4 | **JSON format:** item amounts are objects (`{"coins": 150, "logs": 30}`, like the snapshot's inventory); levels carry their number; `"kind": "house"` or `"producer"`; levels 2 and up carry `upgradeCost` and `upgradeSeconds` (the cost and time to reach that level), level 1 none; a building says `"availableAtStart": true/false`, and the unlock itself is only the research effect `{"type": "unlockBuilding", "building": …}`, from which the factory fills `BuildingDefinition.UnlockedByResearch`; display names (`"name"`) on eras, items, buildings and research; the starting city (era, inventory) is content, so M0-08 doesn't hard-code it; effects are `{"type", "building"/"item", "permille"/"amount"}`. Maps and lists may be left out when empty (`inputs`, `prerequisites`, `effects`, `maxWorkers`, `workersProvided`), other values are required | Arrays of `{item, amount}`; the unlock on the building and on the research (two homes for one fact); recipes as a separate list with ids | One home per fact; readable for content authors; the client renders names from content (`03` → Content pipeline); principle 8 (no game numbers in code) needs the starting city in content | project-wide (content format → `12` row; documented in M0-07b's how-to) |
| 5 | **Rules beyond the spec** (the owner approved them with the plan): max workers and workers provided never drop from one level to the next (an upgrade keeps workers assigned, `04` invariant 9); every capped item has exactly one base cap and an uncapped item none, and a storage bonus targets only a capped item; research slots are exactly 1 (the M0 engine holds one active research, invariant 10); every number is at most 10¹² (a named technical limit), so sums of content numbers (cap + bonuses, clock + durations) can't overflow a `long`; the minimum cycle is checked on **every** level with its own max workers, not only the max level (equal for the M0 numbers, stricter if levels differ) | Leave them to M0-08/M0-09 and fail there at run time | Bad content must fail at load, not as a broken invariant or an `OverflowException` hours into a settle | local (`04` content rules list them) |
| 6 | **Two phases of errors:** shape errors (missing value, bad id, unknown kind or effect type, a value where none is allowed, a number out of the technical range) are collected first; if there are any, the factory stops there, because the definitions can't be built. Otherwise every rule runs and every rule error is listed. Errors come in a fixed order (phase, then rule, then file order), and their path names the place (`buildings[sawmill].levels[2].recipe.labor`) | Run the rules on a partly read content (cascades of follow-up errors); stop at the first error | "Fail fast listing all validation errors" without a list of follow-up noise; a stable order makes the startup message and the tests deterministic | local |
| 7 | **Number types:** `int` for worker counts, level numbers, era numbers, grid size, slots and permille; `long` for quantities, costs, caps, seconds and labor (`04` §9) | `long` everywhere | Matches `04` §9 and the snapshot; sums of worker counts are taken in `long` where they could grow (M0-08) | local |
| 8 | **For M0-07b (decided with the plan):** config key `Content:FilePath` (default `content/mvp-content.json`, relative to the app's base directory; the Api build copies `server/content/*.json` there); the loader uses System.Text.Json with unknown fields and duplicate keys rejected (`UnmappedMemberHandling.Disallow`, `AllowDuplicateProperties = false`, both in .NET 10); `IContentProvider` in Application; the server loads the content before it accepts requests and stops with every error listed | A fixed path without a key | A test can then start the server with a broken file and see it refuse | local (M0-07b) |
