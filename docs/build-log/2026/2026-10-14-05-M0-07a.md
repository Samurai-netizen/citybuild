## Problems and surprises
- The first version of the id contracts had the precomposed `é` on both sides of the "culture-equal" test case, so it compared two identical
  strings. Found by checking the code points before the first run; the test data now uses `\u` escapes (`"caf\u00E9"`, `"cafe\u0301"`,
  `"saw\u00ADmill"`), which also makes the intent visible.
- The first build of the content types had two kinds of analyzer errors, both fixed as the rules ask: IDE1006 on private `const` fields (the
  naming rule `_camelCase` covers every private field, constants included) and CA1864 (`ContainsKey` + `Add` → `TryAdd`, which netstandard2.1
  and Unity have). CA2227 and CA1002 (settable `List`/`Dictionary` properties) did not fire, so the `*Data` classes need no suppression.
- Text with `\u` escapes that I typed into an editing tool sometimes landed as the real character (the soft hyphen in this entry, `ö` in a
  test). Escapes are now written by a script, and the code points are checked (`python3 … ord(c) > 127`) before a commit.
- The step 5 commit (`89dac5d`) was pushed although `dotnet format --verify-no-changes` had failed on two object initializers in
  `ContentReferenceRuleTests` (several properties on one line): the check and the commit were chained with `;` instead of `&&`. Build and
  tests were green. Fixed in the next commit with `dotnet format`; from here on the format check gates every commit (`&&`).
