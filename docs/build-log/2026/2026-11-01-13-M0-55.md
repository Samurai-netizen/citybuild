## Sessions

### Session 1 — 2026-11-02 · Claude Code / claude-sonnet-5-5
- **Plan:** what exists: `ConnectionMonitor` holds the six states (M0-41); the HUD shows the state as a word and a dot (M0-49); the status
  label at the bottom left says it in a sentence (M0-48); a refused token already asks for a poll (M0-54). What is missing is the rest of the
  spec: the age of the last sync, the command buttons switched off with a reason, and the two screens for `Unauthorized` and `IncompatibleVersion`.
  1. **`CommandAvailability`** (Presentation/Ui, a plain class): from a `ConnectionState` it says whether a command may be sent and, if not, the
     reason in words. One home for the rule; tests for every state.
  2. **Switch the buttons off through it:** `BuildingInspectorModel` (− / + / Upgrade), `ResearchNodeModel` (Finance), `PlacementFlowModel`
     (Place). Each model takes the availability, shows the reason as its note, and its flow also refuses the press (the server checks anyway).
     Tests: the enable rule of every button in every state. Pending intents stay in the pending lists and keep being drawn.
  3. **`ConnectionBannerModel`** (words only): for Offline / ServerError / Unauthorized one line with the reason and `Last synced 3m ago`,
     plus the action (`Try again`, `Sign in again`); for IncompatibleVersion the blocking screen's title and message. Tests.
  4. **`ConnectionBanner`** (a `UIDocument`, layout `UI/ConnectionBanner`) and `ConnectionFlow`, wired in `GameRoot`: the banner under the HUD,
     the blocking screen over everything (a press over either stays off the ground). Layout and PlayMode tests.
  5. **A command that fails for want of a connection asks for a poll** (`ConnectionMonitor.ReportCommandError`), so the state does not wait for
     the 120 s poll to turn Offline. Test with the monitor.
  6. **Docs per the recipes, every Docs impact row closed, `/finish-task`.**
