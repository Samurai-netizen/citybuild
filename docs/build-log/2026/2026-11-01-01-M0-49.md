| 2 | Chips: one per item of the city's era or an earlier one, in the content's order (coins, logs, planks in the fixtures). The stock and the cap are plain numbers, the rate is `ProductionDisplay.NetPerHour` | Only items with stock or a rate; a hand-written list | The spec says "one chip per item". Coins have a chip too. A hand-written list would put item ids in code (principle 8) | local |
| 3 | `PerHourText` shows whole items, or one tenth when the rate is not whole (`+12.5/h`), rounded toward zero; a rate under a tenth reads `0/h` and counts as flat; the minus is U+2212 as in the spec's `−30/h` | Whole items only; two decimals | A producer slower than one item an hour (the engine keeps thousandths for that) would read `0/h` in whole items. The text and the trend come from the same rounded value, so a `0/h` is never coloured red or green | local |
| 4 | The connection indicator is a dot and a word driven by `ConnectionState` (`Online`, `Connecting`, `Offline`, `Signed out`, `Update needed`, `Server problem`), a second input to `HudModel.Update` beside the displayed city | Show the connection from `DisplayCity`; reuse `ConnectionStatusModel`'s long sentence | The spec lists the indicator and the display city cannot know the connection. The long sentence (with the error code) stays in `ConnectionStatusView` | local |
| 5 | The model type for the rate text is `PerHourText`, the HUD component will be `HudView` | `RateText` / `Hud` | A static class `RateText` clashed with the property `ItemChipModel.RateText`; a class `Hud` in the namespace `Hud` would shadow it | local |
| 6 | The HUD takes no pointer: every element has `picking-mode="Ignore"`, tested for both layouts and in the scene. `GameRoot.IsOverUi` is not extended | Count the HUD as UI (extend `IsOverUi`) | All screens share one panel (same `PanelSettings`), so a pickable HUD label would make `panel.Pick` hit it and the menu's `IsOverUi` would say "over UI" there. The HUD has no button, and a drag that starts on it should still pan | local |
| 7 | `ConnectionStatus.uss`: the status label moves from top left to bottom left (`bottom: 96px`, above the Build button); `Toasts.uss`: `toast-list` gets a `margin-top: 224px`, not a root padding | Hide the label once connected; put the HUD below the label; a padding on the toast root | The HUD owns the top. The label still carries the error code of a failure, which the HUD's word does not, and `GameRoot` tests read its text. `UiRoot.PadBySafeArea` overwrites the root's padding in code, so a margin is the only offset that survives | local |
| 8 | The ring is drawn with `generateVisualContent` and a `Painter2D` arc on a plain `VisualElement` (float math in the view only: angles for a picture) | A custom `VisualElement` subclass with `[UxmlElement]`; a sprite sheet | A plain element needs no factory and stays in the UXML by name; the engine's integer permille is the only input | local |
| 9 | Not done: a PlayMode test through `GameRoot` (no scene test reaches the connected state without a server); the HUD's look is not checked in the Editor | A fake server in a scene test | `GameRoot`'s HUD wiring is five lines; `HudViewTests` and `HudModelTests` cover the parts. The visual check is a [MANUAL] step for the owner (Follow-ups) | local |
