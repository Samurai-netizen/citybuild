## Decisions
<!-- Every decision, when it is made, including small ones. Scope: local | project-wide (→ 12-decisions.md row) | architectural (→ ADR). -->
| # | Decision | Alternatives considered | Why | Scope |
|---|---|---|---|---|
| 1 | The scaffold placeholder is the construction-site model of CR-0005-T3, not new code | A scaffold built from primitives | The CR already says so (CR-0005 item 5): only the wording of the task changes | local |
| 2 | The ring and the other status visuals update with `DisplayCity.Changed` (once a second), not per frame | A timer of 4 times a second | `ProgressPermille` is in whole city seconds, so more updates would show the same value; the task allows "a few times per second" at most | local |
| 3 | The ring's clock is `city.Clock` of the displayed city, not a `DisplayClock` read | Passing `DisplayClock.Now` into the model | `DisplayCity` advanced the city to `DisplayClock.ElapsedSeconds`, so `city.Clock == DisplayClock.Now`; `ResearchRingModel` does the same, and the model then needs only the city | local |
| 4 | `Stalled` is true exactly when there is a bubble; a building with no recipe (`NoRecipe`, the cottage) is never stalled; a building of a type the content does not know gets no bubble | Showing `NoRecipe` as a stall | A cottage is not waiting for anything the player can fix; an unknown type is already displayed as it is by `DisplayCity` (no exception on the per-second path) | local |
| 5 | The 6 pips cap is `BuildingStatus.MaxPips`, a layout constant | A content value | The task text fixes it as a display limit; it is not a game number (a building with more workers shows 6) | local |
