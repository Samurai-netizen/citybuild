| 2 | The ring and the other status visuals update with `DisplayCity.Changed` (once a second), not per frame | A timer of 4 times a second | `ProgressPermille` is in whole city seconds, so more updates would show the same value; the task allows "a few times per second" at most | local |

| 4 | `Stalled` is true exactly when there is a bubble; a building with no recipe (`NoRecipe`, the cottage) is never stalled; a building of a type the content does not know gets no bubble | Showing `NoRecipe` as a stall | A cottage is not waiting for anything the player can fix; an unknown type is already displayed as it is by `DisplayCity` (no exception on the per-second path) | local |
| 5 | The 6 pips cap is `BuildingStatus.MaxPips`, a layout constant | A content value | The task text fixes it as a display limit; it is not a game number (a building with more workers shows 6) | local |
| 6 | The ring is 33 shared meshes (fill step 0 to 32, each a part of the same vertices); a building swaps a mesh reference | One mesh per building rewritten each second; a shader with a fill amount | Swapping a reference allocates nothing and needs no shader; 32 steps are 3 % of a cycle each, finer than the one-second tick can show | local |
| 7 | The ring is a mesh and the bubble and pips are sprites, all drawn with the pipeline's default sprite material (read from a probe `SpriteRenderer`, no `Shader.Find`) | A custom unlit shader; UI Toolkit in world space | Same reason as `PlaceholderArt.CreateMaterial`: a shader looked up by name could be stripped from a device build; world-space UI Toolkit is not in the stack | local |
| 8 | A building with nothing to show (a cottage, an idle producer that can run) has no status object; it is made the first time there is something | A status object on every building | 64 tiles x 13 objects would be about 800 objects for nothing | local |
| 9 | The three bubbles differ by rim colour (amber, red, blue), by picture (workers, or the item) and a strike across a missing input; storage full has no extra mark | Colour alone; new glyph art | Colour alone is weak for colour-blind players; art for glyphs is not in the task. The owner can ask for glyphs after the [MANUAL] look | local |
| 10 | `StatusArt` is `public`, the status view's `Create` and `Apply` are `internal` | `InternalsVisibleTo` for the tests | The project uses none; the tests need `StatusArt.StepOf` and `BubbleColor` | local |
| 11 | A stalled building makes the engine's small `StallReason` object once a second (inside `Describe`); a showing with no stalled building allocates nothing and a test says so | Re-deriving the reason in the client | The reason is engine logic (`StallReason.Of`), the client must not copy it; one small object per stalled building per second is no per-frame allocation | local |
| 12 | The status turns to the camera's rotation at each showing (once a second), not per frame | `LateUpdate` per status | The camera only pans and zooms in M0, so its rotation never changes; a rotating camera later would need a per-frame step then | local |
| 13 | The stalled look is a property block per renderer: the base colour times 0.65 and an emission of grey 0.55 x 0.35 (`StalledTint.Mix`, `Grey`); the shared material gets `_EMISSION` on | Only a darker tint (a multiply cannot lower saturation); a second desaturated palette and material; a custom shader | The CR asks for a per-renderer property on the shared material. Not covered by a test (no way to make such a body for a known type that can stall); covered by the [MANUAL] look only | local |

## Problems and surprises
- The first try of the stalled look failed: the `.mat` file with `_EMISSION` in `m_ValidKeywords` and a black emission came back from Unity without the keyword. URP's material code keeps the keyword on only when the material is not flagged `EmissiveIsBlack` (`m_LightmapFlags` 4); it needed an emission above zero (0.002, under one 8-bit step) and `m_LightmapFlags` 2. Unity leaves the file unchanged now (the mirror's copy equals the repository's after the run), and `ArtImportTests` guards the three values.
