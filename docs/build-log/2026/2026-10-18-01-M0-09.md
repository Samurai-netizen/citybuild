## Problems and surprises
- Every new test passed on its first run, so seven rules were broken by hand to see the tests fail (decision 19). One change survived: the
  order "research before building completions" at the same second can't be observed with the M0 effect types.

## Follow-ups
- M0-10 ("research completion before building completions at the same t"): with the M0 effects the order is not observable (decision 19).
  The test can show that the result is the same either way, plus that a cycle starting in that second already uses the research; the order
  itself becomes testable with the first effect that changes a completion (for example a max-workers bonus and auto-staffing).
- M0-16: `CityState.HasItems`, `AddItems` and `RemoveItems` enumerate `IReadOnlyList` with `foreach`, which allocates an enumerator per call
  in the loop; the new loop code uses indexed loops (decision 9).
