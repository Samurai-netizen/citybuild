## Decisions
<!-- Every decision, when it is made, including small ones. Scope: local | project-wide (→ 12-decisions.md row) | architectural (→ ADR). -->
| # | Decision | Alternatives considered | Why | Scope |
|---|---|---|---|---|
| 1 | `ConnectionState` and `PollScheduler` live in `CityBuilder.Client.Core` (no Net types, so they test with a plain clock); `ConnectionMonitor` lives in `CityBuilder.Client.Net` next to `CommandSender` | all in Presentation next to `StartupFlow` | The monitor needs `ApiClient`, `AuthService` and `SnapshotMapper` (Net); the views read its state from `GameRoot` | local |
| 2 | The monitor is built after a successful start, so it begins `Connected`; a failed start keeps today's "Not connected" screen and does not poll | build the monitor first and report the start into it; poll the city before content is loaded | The task's poll needs the loaded content version and the dev login; a start that failed has neither, and M0-42 only needs reconnecting after a connected start. Restarting the app retries the start | local |
| 3 | The start flow's `GET /city` is the poll on start: the scheduler counts its first 120 s from the monitor's creation | poll again at once after the start | Two identical requests back to back add nothing | local |
| 4 | `IncompatibleVersion` means: a snapshot whose `contentVersion` is not the loaded content's (the snapshot is not applied), or a 2xx answer that is not the contract's (`CLIENT_INVALID_RESPONSE`, status 2xx). A `CLIENT_INVALID_RESPONSE` with another status (a proxy's page) is `ServerError`. It is not a terminal state: polling goes on, and the next usable answer of the right content is `Connected` again | the task names the state but no rule; `05` only says the client refetches `/content` when the version differs (not built) | `05` Versioning and the "matching builds" limit in the Net module doc are the only version rules there are; refetching content mid-session would need the display city rebuilt, which no task covers | local. Owner: say if you want other rules |
| 5 | `AUTHENTICATION_REQUIRED` on a poll: forget the token, one new login, one repeat of `GET /city`. A second refusal, or a refused login, is `Unauthorized`; a login that gets no answer is `Offline`. Each later poll tries the same once more | stop polling after `Unauthorized` | "re-login once, then show the state" is per poll; a stopped poll would never recover from a login that failed only because the server was restarting | local |
| 6 | A `RATE_LIMITED` poll changes no state (a rate-limited login is `Unauthorized`) | show `ServerError` | The server is reachable and the next poll in 120 s is far past any window; flipping the label to an error for a rate limit would be wrong | local |
| 7 | "After reconnect" = the device's `Application.internetReachability` going from `NotReachable` to reachable asks for a poll at once. A server that was down while the device had a network is found by the next 120 s poll (M0-42 says so) | poll every few seconds while `Offline` | The task fixes the 120 s rhythm; a faster retry is a policy change for the owner | local |
| 8 | `TickAsync` is called every frame by `GameRoot.Update`; it is cheap when nothing is due and never throws (a cancel ends it quietly); a request made during a poll is served right after it | a coroutine or a timer; throw on cancel | One driver, and no timer to stop on destroy; the scheduler already makes sure only one poll runs | local |
