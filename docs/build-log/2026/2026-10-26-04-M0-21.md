## Decisions
<!-- Every decision, when it is made, including small ones. Scope: local | project-wide (→ 12-decisions.md row) | architectural (→ ADR). -->
| # | Decision | Alternatives considered | Why | Scope |
|---|---|---|---|---|
| 1 | Isolation: a fresh database per test, `CREATE DATABASE … TEMPLATE` from a database migrated once per run (an empty one from `template0` for the migration tests) | a transaction rolled back per test; truncating one shared database; Respawn | works with several contexts and the in-memory server's own scopes (the task's "data survives a new DbContext", and M0-22's own transactions), lets test classes run in parallel, costs a few ms per test; a rollback can't span the server's connections, truncation serializes the tests, Respawn is a new dependency | local |
| 2 | One container per run as an xUnit v3 assembly fixture that starts lazily on the first database a test asks for | a collection fixture; starting in `InitializeAsync` of the fixture | xUnit creates assembly fixtures even when the filter leaves only fast tests, so a lazy start keeps the fast suite free of Docker; a collection fixture would put every integration test in one serial collection | local |
| 3 | The container image is `postgres:18.6`, the tag of `docker-compose.yml` (`PostgresServer.Image`) | the Testcontainers default image | the stack pins 18.6 (`06`); the test runs on the server version the game uses | local |
| 4 | `PostgresApiFactory` replaces the server's `TimeProvider` with a `FakeTimeProvider` at 2026-10-26 12:00 UTC (`Clock`), sets the connection string and turns the startup migration off; a test turns it on with `WithWebHostBuilder` | the system clock; a second factory class for the migration test | `.claude/rules/tests.md` (time only through `FakeTimeProvider`); one factory, as `ApiFactory` does for the in-memory tests | local |
| 5 | The template is migrated over a connection without pooling, and statements on the maintenance database use one too | the default pool and `ClearPool` | `CREATE DATABASE … TEMPLATE` fails while any connection to the template is open; a pooled one would stay open | local |
| 6 | No own wrapper for "Docker isn't running" | an `InvalidOperationException` naming `docs/testing/README.md` | Testcontainers already throws `DockerUnavailableException` with a clear message from `Build()`, before any wrapper could catch it; the docs page says Docker is required | local |
| 7 | Database statements in the fixture are built from names the fixture makes itself (`test_<guid>`, the template) | parameters | PostgreSQL doesn't take parameters for database names in `CREATE`/`DROP DATABASE`; no outside input reaches them | local |
