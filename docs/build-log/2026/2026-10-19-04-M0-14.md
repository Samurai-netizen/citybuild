## Decisions
<!-- Every decision, when it is made, including small ones. Scope: local | project-wide (→ 12-decisions.md row) | architectural (→ ADR). -->
| # | Decision | Alternatives considered | Why | Scope |
|---|---|---|---|---|
| 1 | The property harness lives in `Simulation.Tests/Properties/`, test code only, no new packages | A separate test project; a property-testing package (FsCheck, CsCheck) | The task says no new packages; the harness needs only the engine and the existing fixtures | local |
| 2 | Structural equality = each city flattened into an ordered list of `(path, value)` fields (clock, era, next id, stock per item, every building field by id, completed and active research), compared by path; the first difference in that order is returned as `path: expected X, actual Y`, a side without the path shows `absent` | Compare `CityDump` text line by line (the whole stock is one line, so it can't name the item); reflection deep-compare (sees private fields, breaks when the engine renames one, and the server will only see public members) | Names the exact field, reads only public members, stable order | local |
| 3 | The private constant is `_absent` | `Absent` | The repo's naming rule IDE1006 wants the `_` prefix on private constants too | local |
| 4 | `ReportTotals` sums reports on the test side (seconds and quantities add, completions are listed together and sorted, era flag ORed) | `InternalsVisibleTo` to build a `SettlementReport`; adding a `Plus` to the engine | `SettlementReport`'s constructor is internal and the engine needs no sum; test code shouldn't change the engine | local |
| 5 | The random source is SplitMix64 written in the tests (`SeededRandom`), pinned by its reference values | `System.Random(seed)` | .NET doesn't promise that the seeded `Random` gives the same sequence in later versions; a printed failing seed must reproduce on any runtime. 30 lines, no package | local |
| 6 | Operations are records (`PlaceBuilding`, `UpgradeBuilding`, `AssignWorkers`, `StartResearch`, `Advance`) that run as the server runs them: the mutation through `CityRules`, then a zero-length advance; time through `Simulator.Advance`. A rejected command is dropped from the list and counted | Keep rejected commands in the list; generate only commands known to succeed (would copy the rules' checks into the tests) | The list holds exactly what changed the city; the rules stay the only judge. That a rejection changes nothing is the engine's contract (rule tests), and property 1 replays every list, so a violation would show | local |
| 7 | Copies of a generated city come from replaying its operations on a new starting city (`CityHistory.Copy`) | A clone method on `CityState`; the public restore constructor with every field | No engine change, and the copy only uses the rules too | local |
| 8 | Commands are random but aimed: a free tile; a type the city doesn't have yet in 75 % of placements (else any type); an existing building; 0..`MaxWorkers` of its level; a research node not completed yet | Fully uniform commands | Uniform choices spent golden-v1's 700 coins on houses and research, so the Trading Post (coins come only from it) was placed in 0 of 500 seeds; 50 % new types gave 1, 75 % with 80 attempts gives 11 | local |
| 9 | Mix per attempt: 35 % advance, 20 % place, 20 % workers, 10 % upgrade, 15 % research; a history tries a random 0..80 commands. Gaps: a quarter each in 0–60 s, 61–600 s, 601 s–cap, cap+1–4 caps | Fixed history length; gaps only within the cap | Random lengths show cities at every age; a quarter of gaps make the city dormant, which timer invariance needs. The limits are test parameters, not game numbers | local |
| 10 | Every property runs over two frozen contents: golden-v1 (the game's M0 numbers) and the rule fixture (two eras, a locked chain building, an uncapped output from the start, refunding upgrades). `CityGeneratorTests` holds floors (each command ≥ 20 accepted; ≥ 100 seeds with research and with a gap beyond the cap; ≥ 20 with an upgrade done; ≥ 5 with a locked building, an input cycle, a frozen cycle) and prints the counts | Only golden-v1; the live `mvp-content.json` | Golden-v1 alone reaches chains rarely; live content would change seeds' histories with balance changes. The floors make a generator change that stops reaching a situation fail instead of silently weakening the properties | local |
| 11 | The seeds are 0..499 (`PropertyContent.Seeds`), all run in one test per property and content | One xUnit case per seed (1000s of cases in the report) | Keeps the test list readable; the failure message names the seed | local |
