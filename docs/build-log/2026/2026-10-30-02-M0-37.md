## Decisions
<!-- Every decision, when it is made, including small ones. Scope: local | project-wide (→ 12-decisions.md row) | architectural (→ ADR). -->
| # | Decision | Alternatives considered | Why | Scope |
|---|---|---|---|---|
| 1 | Async API: `Task<ApiResult<T>>` with a `CancellationToken`, not `Awaitable` | `Awaitable` | The task says Awaitable or Task. An `Awaitable` is pooled, can be awaited once and needs the player loop, so EditMode tests with a fake transport would hang. `Task` continues on Unity's main thread through its synchronization context. | local |
| 2 | Failures as results: Rule refusals, network failures, timeouts and bad bodies return `ApiResult<T>` with an `ApiError`; only a cancelled token throws `OperationCanceledException` | Exceptions (`ApiException`) | `14`: business-rule failures are results. `CommandSender` (M0-40) branches on the code without try/catch. | local |
| 3 | `ApiError` members: `Code`, `Status`, `Detail`, `TraceId` as the task says, plus `RequestId` (Guid?) and `RetryAfterSeconds` (int?); no `Title` | Exactly four members | `05` says `RATE_LIMITED` is retried after `Retry-After`, and a command is correlated by its `requestId` (M0-40). `title` is for humans and may change, `detail` is enough for logs. | local |
| 4 | Client-side codes: Three codes made up by the client: `CLIENT_NETWORK_ERROR` (status 0), `CLIENT_TIMEOUT` (status 0), `CLIENT_INVALID_RESPONSE` (the HTTP status: malformed or non-JSON body, 502 page, wrong shape, error body without `code`). The body is never copied into the error. | Reuse `INTERNAL_ERROR`; a separate error kind | A 502 from a proxy is not the server's `INTERNAL_ERROR`. The `CLIENT_` prefix keeps the two lists apart; a message table (M0-47) needs a message for each. `ClientErrorCodesTests` holds the server part equal to the table of `05`. | local |
| 5 | DTO shape: Immutable classes bound through `[JsonConstructor]`, named `…Dto` (the engine has `BuildingKind`), `[JsonObject(ItemRequired = Always)]` with `AllowNull` on the members `05` writes as `null`, concrete `Dictionary<string, long>` and `List<T>` | Mutable setters; `IReadOnlyDictionary`; no suffix | A missing member is a refused answer instead of a silent 0; the null members are exactly those `05` lists. Newtonsoft builds `Dictionary`/`List` without reflection tricks that IL2CPP may strip (`ReadOnlyDictionary<string,long>` might be missing on a device). | local |
| 6 | Wire enums: `BuildingPhaseDto`, `BuildingKindDto`, `ResearchEffectTypeDto` with `[EnumMember]` wire names and `StringEnumConverter`; an unknown value fails the answer | Plain strings | The task says enums as strings. Names such as `Producing` are compared in the compiler, not by text. Client and server ship together in M0; a new phase comes with a new era (`24`). | local |
| 7 | Unknown members: Members the DTOs don't have are ignored | `MissingMemberHandling.Error` | An additive server change (a new field) must not break an older client; `contentVersion` is the compatibility signal. | local |
| 8 | Timeout: `ApiClient` owns the timeout (a linked `CancellationTokenSource.CancelAfter`), the transport only obeys its token; a timeout is `CLIENT_TIMEOUT`, a cancelled caller token throws | `UnityWebRequest.timeout` | The same behaviour on every transport, and a fake transport can test it (`ApiClientTests`). | local |
| 9 | No static state: `ApiJson` is an instance each `ApiClient` owns; `ApiClient` takes `baseUrl`, `timeoutSeconds` and an `IApiTransport`, not the `ScriptableObject` | A static settings object; passing the asset in | `09`/`unity.md`: no static mutable state. Plain values keep `ApiClient` testable without creating assets. `GameRoot` (M0-38) passes `settings.BaseUrl` and `settings.RequestTimeoutSeconds`. | local |
| 10 | Config asset: `ApiClientSettings` (`ScriptableObject`: `baseUrl` `http://localhost:8080`, `requestTimeoutSeconds` 15) with its asset in `Resources/Config/`, written by hand (a few lines of YAML with the script's GUID) and loaded by `ApiClientSettingsTests` | Create it in the Editor; a code default | `09` rule 1: no Editor GUI. The test fails if the asset loses its script. Hand-editing a scene or prefab is what the rule warns against, not a 15-line asset. | local |
| 11 | Tests without Newtonsoft: The Net tests don't reference Newtonsoft: round trips compare the written text with the fixture byte for byte (the DTOs keep the server's member order) | Add `Newtonsoft.Json.dll` to the EditMode test asmdef | `ClientAssemblyTests` holds the test asmdefs to `nunit.framework.dll` only; loosening a guard is not mine to decide (`.claude/rules/tests.md`). The byte-for-byte test is also stricter than a JSON comparison. | local |
| 12 | Real transport test: `UnityWebRequestTransportTests` run the real transport against an `HttpListener` on a free local port (`[UnityTest]` coroutines) | Only a manual walk against the server | The wire is covered in `test-unity.sh`, not only by hand. A walk against the real server is still done at the end. | local |
