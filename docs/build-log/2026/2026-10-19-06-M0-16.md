## Problems and surprises
- The first measurement was 144 ms (Release), three times the target: every mine start summed the ore reservations over all 64 buildings.
- With the default tiered JIT, dynamic PGO halves the cost (97 → ~50 ms before step 4d) and adds ±10 ms of noise, so ablation needed
  `DOTNET_TieredCompilation=0`. Unity's runtimes have no dynamic PGO: there the worst case costs closer to the no-PGO 67 ms.
- Inside the full parallel suite the timing was 2–10× slower (decision 13).

## Follow-ups
- If the budget needs more margin (slower dev machines, Unity): the item tables (`ItemTotals`) find items by binary search with string
  compares, several times per start and completion; dense integer item indices would cut most of what is left (decision 12). A design
  change for its own task or CR.
- Client display prediction (M0-37 onward): each `Advance` now allocates a little more once per call (queue arrays, two sources), not
  per event. If the client advances every frame, measure the garbage there and consider advancing per second or reusing the structures.
