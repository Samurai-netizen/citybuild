## Decisions
<!-- Every decision, when it is made, including small ones. Scope: local | project-wide (→ 12-decisions.md row) | architectural (→ ADR). -->
| # | Decision | Alternatives considered | Why | Scope |
|---|---|---|---|---|
| 1 | `SettlementWindow` is a `readonly struct` in `Settlement/` with `static Compute(lastSettledUnixSec, nowUnixSec)` and the properties `ElapsedSeconds`, `NewLastSettledUnixSec`, `IsClockBehind` | A value tuple, as the spec writes it (`→ (elapsed, newLastSettled)`); a class | Named and documented members that callers in other assemblies see; no allocation per settle; the spec's call shape `SettlementWindow.Compute(…)` stays | local |
| 2 | The window says when the server clock is behind (`IsClockBehind`) instead of logging: the engine has no logging (`.claude/rules/simulation.md`), and the server writes the warning of `04` §1 | The engine logs; the caller compares the two seconds itself | The rule bans logging in the engine; one place decides "behind", and the caller only reacts | local |
| 3 | `Compute` subtracts with `checked` and doesn't range-check its inputs; an overflow throws `OverflowException` | Reject negative seconds with `ArgumentOutOfRangeException` | Unix seconds are any `long` in principle; the only real failure, an overflow, is caught by `checked` (`04` §9: overflow is a bug, not a wrap) | local |
| 4 | `FakeTimeProvider` from `Microsoft.Extensions.TimeProvider.Testing` 10.10.0, referenced by `Application.Tests` only | 10.11.0 (the newest); no package, a hand-written fake `TimeProvider` | The package is on the approved list of `14` and `08` names `FakeTimeProvider`, so no gate; 10.10.0 is the newest release older than two weeks (2026-09-09; 10.11.0 is from 2026-10-14) | local |
| 5 | Application folder `Cities/` holds the port, the aggregate and the use case; `SettleCity` is a plain class with `ExecuteAsync(playerId, ct)`, no interface | `Commands/SettleCity/` (recipe of `19`); `Settlement/` | Settling is not a player command (no `requestId`, no receipt), and the city is the feature; `14` allows interfaces only at layer boundaries | local |
| 6 | `CityAggregate` (player id as `Guid`, `CityState`, `LastSettledUnixSec`) lives in Application; `MarkSettled` refuses a second before the current one | A Domain type; the last settled second inside `CityState` | The last settled second is wall time that only the server knows (`06`: `last_settled_unix` next to `clock_seconds`), so it stays out of the engine; Domain has no city concept yet, and M0-20 shapes the aggregate for persistence; `players.id` is a `uuid` | local |
| 7 | `ICityRepository` is a skeleton: `LoadForUpdateAsync(playerId)` returns a city (every player has one from the first login) and `SaveAsync(city)` | The full port of M0-20 now (ledger, receipt, unit of work) | The task asks for a skeleton with an in-memory fake; M0-20 owns the port's shape, M0-22 the lock and transaction | local |
| 8 | `SettleCity` doesn't run the closing zero-length advance and doesn't log the warning of a clock behind; its result carries the window (`IsClockBehind`) | Do both now; add `Microsoft.Extensions.Logging.Abstractions` to Application | M0-23 lists the zero-length advance and completes the use case; logging needs a package Application doesn't have, and the approved list of `14` doesn't name it, so it would be G-Dependency; follow-up for M0-23 | local |
| 9 | Now is floored with `DateTimeOffset.ToUnixTimeSeconds()` | Own division of ticks or milliseconds | It rounds down for every value (ticks since year 1 are never negative), and it is the BCL's own conversion; the 300 ms test fails if the rounding changes | local |
| 10 | The settle tests use a small content in code (the production cap is the M0 value, 8 h) and arrange the city with `CityRules` from the starter city | The game content `server/content/mvp-content.json`; a city made with the `CityState` constructor | Tests that don't depend on balance numbers; a city reached by the rules is a canonical one, like a stored city | local |
| 11 | "Clock moved backwards" is tested with a last settled second ahead of the fake clock | Setting the fake clock back | `FakeTimeProvider.SetUtcNow` throws `ArgumentOutOfRangeException` for an earlier time (its XML docs); a stored second ahead of now is exactly what the server sees after its clock was set back | local |
