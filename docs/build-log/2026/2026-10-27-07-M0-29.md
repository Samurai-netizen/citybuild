## Problems and surprises
- **The web JSON defaults read numbers from strings** (`"x":"2"` was accepted); found by the wrong-shape test, fixed with
  `JsonNumberHandling.Strict` (decision 3).
- **The framework's own 400** has no `code`: in Development (the test servers' environment) it is the developer exception page as Problem
  Details with the exception, elsewhere an empty body. Left to M0-34, which owns binding failures → `INVALID_ARGUMENT` (decision 3).
- **My expectation, not the server:** two players' snapshots of identical starter cities are the same text (a snapshot names no player).
  The stored rows prove the second command ran in its own city; the assertion was replaced by a comment before the first commit.
- **Review finding 1 (fixed, decision 10):** the 200 body had no schema in the OpenAPI document, because the handler writes text.
- No agents were used (OD-9). Self-review: line by line (the task is `[O]` and touches security): the body rules, the outcome mapping
  against `05`, the endpoint's thinness (no write outside the pipeline), what a client's text can reach (`BuildingTypeId` throws only for
  null or empty, refused by the shape check first), the replay bytes, the tests' arithmetic (costs, end seconds, completion order).
