## Decisions
<!-- Every decision, when it is made, including small ones. Scope: local | project-wide (→ 12-decisions.md row) | architectural (→ ADR). -->
| # | Decision | Alternatives considered | Why | Scope |
|---|---|---|---|---|
| 1 | The one-city tests queue the settles behind a lock the test holds and wait until PostgreSQL shows them all waiting (`pg_stat_activity`), then move the clock and let go | A free race (20 `Task.Run` settles while the clock moves on): tried first, but its settles didn't overlap — the mutant without `FOR UPDATE` still passed it | Contention that always happens, so the test fails when the lock is missing; the waves test keeps time passing between the contended settles | local |
| 2 | The queued settles run on a server with a 30 s lock timeout | The default 3 s | The first queued settle waits while the other 19 are started; 3 s could run out on a slow CI machine. The default timeout's own behaviour is tested in `CityTransactionDatabaseTests` | local |
| 3 | "Different cities don't block each other" is two tests on a server with a 200 ms lock timeout: settles of 19 cities while one is held, and 20 transactions that each wait inside until all 20 hold their locks | Measuring durations | A wait for a lock turns into a failure instead of a slow test; the barrier proves the 20 locks are held at the same moment | local |
| 5 | A transaction disposed without a commit clears the context's change tracker (`UnitOfWork`'s transaction) | Clearing in the Application runner (it has no tracker); detaching only the city's rows; leaving it and relying on the `state_version` guard | A rollback must leave nothing a later save could write; the version guard would not catch it, because the rollback also undid the change that made the version stale. Clearing everything is right: every row the context tracked belongs to the rolled-back transaction | local |
| 6 | Audit points that were only checked by reading get a test: a city with every time, labor and quantity beyond 32 bits round-trips on PostgreSQL; a model test on CLR types (`DateTimeOffset` ↔ `timestamptz`, no `DateTime`, `long` ↔ `bigint`) | Recording them as checked | Each keeps holding when someone adds a column | local |
| 7 | `CityRepositoryDatabaseTests.SaveChangesAsync_StaleStateVersion_…`: the stale scope's load transaction now commits instead of rolling back; its assertions are unchanged | Changing the fix so that a rollback keeps the rows | The test needed rows tracked across a rolled-back transaction, which is exactly the leak the fix closes; with a commit the scenario is the same (load, lock released, another save, stale save) | local |
| 4 | Test helpers shared by the database tests: `DatabaseLocks` (lock timeout, holding a lock, waiting for waiters) and the ledger and state helpers moved to `DatabaseCities` | Copying them into the new class | `.claude/rules/tests.md`: fixtures, not copied setup | local |
