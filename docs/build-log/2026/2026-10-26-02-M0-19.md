  1. **Docker:** `docker-compose.yml` at the repo root, service `postgres`, image `postgres:18.6`, a named volume at
     `/var/lib/postgresql` (checked on hub.docker.com/_/postgres on 2026-10-26: from 18 the image's `VOLUME` is `/var/lib/postgresql`
     and `PGDATA` is `/var/lib/postgresql/18/docker`), port bound to `127.0.0.1:5432`, healthcheck `pg_isready`, credentials
     `POSTGRES_USER`/`POSTGRES_PASSWORD`/`POSTGRES_DB` from the gitignored `.env` (required: compose stops if one is missing), and a
     committed `.env.example`.
  2. **Packages:** `Npgsql.EntityFrameworkCore.PostgreSQL` (Infrastructure; brings EF Core 10), `Microsoft.EntityFrameworkCore.Design`
     (Api, design time only, `PrivateAssets=all`), the local tool `dotnet-ef` pinned in `.config/dotnet-tools.json`
     (`dotnet tool restore`). All on the approved list of `14` (EF Core 10, Npgsql); lock files updated.
  3. **Persistence model:** `Infrastructure/Persistence/CityBuilderDbContext`, one row class per table in `Persistence/Rows/`
     (`PlayerRow`, `CityRow`, `CityInventoryRow`, `CityBuildingRow`, `CityResearchRow`, `CommandReceiptRow`, `LedgerEntryRow`), one
     `IEntityTypeConfiguration` each in `Persistence/Configurations/`: tables, columns, types, nullability, keys, unique, check
     constraints and the index exactly as in `06`; `state_version` a concurrency token. Fast tests (no Docker) read the EF model:
     every table, column, type, null rule, key, unique, check, index and the concurrency token as in `06`, and every name snake_case.
  4. **Configuration and registration:** `AddCityBuilderPersistence` in Infrastructure; connection string `ConnectionStrings:CityBuilder`
     from user-secrets (a `UserSecretsId` in Api) or the environment (`ConnectionStrings__CityBuilder`), never a committed file;
     required at startup (`ValidateOnStart`). `Database:ApplyMigrationsAtStartup` (options class, `true` in `appsettings.Development.json`).
     The in-memory API tests get one shared test factory with a placeholder connection string and migrations off. Tests: a blank
     connection string stops the start.
  5. **Migrations at startup, Development only:** before the server accepts requests, `MigrateAsync` runs when the environment is
     Development and the flag is on. The flag on in any other environment stops the start with an error (never a silent migration).
     Tests for both rules.
  6. **Initial migration** `InitialCreate` with `dotnet ef migrations add` into `Infrastructure/Persistence/Migrations`, committed. A
     fast test: the model has no changes the migrations don't cover (`HasPendingModelChanges`).
  7. **Run it against the compose database:** `docker compose up -d postgres`, `dotnet run` (Development) applies the migration;
     check the tables and constraints with `psql` and `__EFMigrationsHistory`, run it a second time (no-op), report the result.
     Needs Docker Desktop running (it is not running on this machine now).
  8. **Docs:** new `docs/how-to/add-migration.md` (+ sidebar, how-to index); `docs/getting-started.md` (Database section, Run rows,
     configuration keys); module docs Infrastructure and Api; `06` "Built so far"; AGENTS.md command mark `[M0-19]` (protected);

| # | Decision | Alternatives considered | Why | Scope |
|---|---|---|---|---|
| 1 | Branch `task/M0-19-ef-core-docker` | — | the task's slug | local |
| 2 | Row classes named `<Table>Row` in `Persistence/Rows/`, separate from Simulation types | entity names like `City`; one folder | `06`: persistence models ≠ Simulation types; the suffix keeps the two apart when M0-20 maps them | local |
| 3 | `players.id` and `cities.id` are set by the application (no database default) | `gen_random_uuid()` default | ids are part of the command flow (M0-24); the database only stores them | local |
| 4 | Wall times (`created_at`, `updated_at`) are `timestamptz` ↔ `DateTimeOffset` (UTC); simulation times stay `bigint` | `DateTime` | `06`: wall timestamps `timestamptz` (UTC); Npgsql requires offset 0 | local |
| 5 | `ledger_entries.ref_type` and `ref_id` are nullable; the other columns of `06` without `null` are `NOT NULL` | all `NOT NULL` | a `STARTING_GRANT` has no reference; `06` marks every other nullable column | local |
| 6 | Design time: `dotnet ef` with Api as the startup project | a design-time factory in Infrastructure | the standard EF setup; the host is stopped right after `Build()`, so nothing else runs | local |
| 7 | Startup migration only in Development; the flag set anywhere else stops the start | ignore the flag elsewhere | task step 4 "never in other environments": a loud failure instead of a silently ignored setting | local |
| 8 | snake_case names written explicitly in every configuration (`ToTable`, `HasColumnName`, constraint and index names); a test checks every name | own naming convention; `EFCore.NamingConventions` (G-Dependency) | owner's choice: nothing hidden, each name can be checked against `06` | local |
| 9 | `Infrastructure/Persistence/Migrations` is generated code: `generated_code = true` in `.editorconfig` and an exempt folder of the doc checker | hand-written comments in every generated file (the snapshot is rewritten by each migration) | owner's choice; EF writes these files, a person never edits them (`06`: never edit an applied migration) | local (G-Tests, approved) |
| 10 | Foreign keys: `cities.player_id` → `players`; `city_inventory`, `city_buildings`, `city_research` → `cities` with `ON DELETE CASCADE`; `ledger_entries.city_id` → `cities` and `command_receipts.player_id` → `players` with `ON DELETE RESTRICT`; written into `06` | no foreign keys | owner's choice; the city owns its state rows, and the audit rows must not disappear with a city | local (the `06` text is extended, not broken) |
| 11 | Compose: named volume `postgres-data`, `restart: unless-stopped`, optional `POSTGRES_PORT` (default 5432), required variables with `${VAR:?message}` | bind mount under `.data/`; defaults for user and password | a named volume needs no host path and works the same on every OS; a required password is never a guessable default | local |
| 12 | EF Core pinned at 10.0.14 (latest 10.0 patch) through an explicit `Microsoft.EntityFrameworkCore.Relational` reference in Infrastructure; Npgsql provider 10.0.3 | let the provider pull its minimum EF Core (10.0.4) | without it, Infrastructure would get EF Core 10.0.4 and Api (through the Design package) 10.0.14: two patch versions in one app | local |
| 13 | The `dotnet-ef` tool manifest is `dotnet-tools.json` at the repo root, not `.config/dotnet-tools.json` as the plan said | move it to `.config/` | the .NET 10 SDK writes and finds it there (`dotnet new tool-manifest`); fewer surprises with the SDK's default | local |
