## Sessions

### Session 1 — 2026-11-02 · Claude Code / claude-sonnet-5-5
- **Plan:** one task for every screen (owner: "do everything in one go, even if it will take an hour"). The owner's look is the acceptance, and I cannot
  see the Editor, so the plan starts with a way to see:
  1. **A screenshot harness** that lives only in the scratch copy of the project (not committed): a PlayMode test that builds each real screen with
     sample data on a render texture of the size of a phone (2400 × 1080, also 1920 × 1080 and 1280 × 720) and writes PNGs I can look at. "Before" shots first.
  2. **Scale and tokens.** Palette from the art (`art/blender/palette.py`: plaster, wood, wood_dark, thatch, grass, red, blue, gold) as wood and
     parchment (look "b"). A scale where one panel unit is about one dp on a landscape phone, so 48 is a 48 dp touch target. `Common.uss` with the tokens
     and the shared classes; `PanelSettings` reference resolution and match changed to it.
  3. **Every stylesheet rewritten on the tokens**, one screen at a time, each checked on a screenshot: HUD, toasts, status label, build menu and cards,
     placement bar, inspector, research screen, welcome-back report, connection banner and blocking screen, fatal error screen. Fixed offsets (224, 124, 108)
     become one HUD-height token. C# that mirrors a size or sets a colour (safe-area `BasePadding`, the connection dot) follows.
  4. **Tests:** a style-rules EditMode test (every layout imports `Common.uss`, no colour or font-size literal outside it, buttons use the shared
     classes); the layout tests keep passing; the whole Unity suite on the copy.
  5. **Docs per the recipe, every Docs impact row closed, [MANUAL] look for the owner, `/finish-task`.**
- **Done:** write-ahead (the CR is approved with one task; this entry; resume point). The branch is stacked on `task/CR-0007-proposal` (PR #78, not merged
  yet): the CR file it needs is in that PR, and the owner asked for no stops (decision 1).
  Steps 1 to 4 done. The harness (a PlayMode test in the scratch copy only) renders each real screen on a render texture of a phone's size, and the PNGs
  were read with the Read tool. "Before" at 2400 × 1080: every screen overlapped the others (the HUD, the inspector, the toasts and the buttons in one pile),
  text was cut off, the scrollbars and the Continue button were Unity's defaults. Root cause found on the way: `PanelSettings` was `ConstantPhysicalSize`
  (scale mode 1, reference dpi 96), so a unit was 1/96 inch on the device's own density and the UI was physically huge on a phone; my first change of
  the reference resolution did nothing until the mode was changed to `ScaleWithScreenSize` (2). A panel on a render texture scales by the Editor's screen,
  not by the texture, so the harness emulates "match height, reference 400" with a constant scale of height / 400; the first shots at 2400 × 1080 were drawn
  too big because of that and were redone.
  Done: `Common.uss` (tokens: wood and parchment from the art palette, 3 + 2 font sizes, spacing, radius, 48 touch target, HUD height) and its shared classes
  (text, panels, scrim, button variants, thin scrollbars); every layout and stylesheet rewritten on it (HUD in one wood bar, build tray, placement bar, a
  two-column inspector, compact research nodes with the Finance button beside the text, welcome-back card, banner, blocker, fatal screen); toasts moved to
  the bottom left; `SharedLookTests`. Unity on the copy: EditMode 927 / 927, PlayMode 165 / 165.
- **Stopped at / next:** docs per the recipe, then `/finish-task`.
