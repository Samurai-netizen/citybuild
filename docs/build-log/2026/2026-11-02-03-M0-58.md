## Sessions

### Session 1 — 2026-11-02 · Claude Code / claude-sonnet-5-5
- **Plan:** (owner's answers below fix the two open points: new content is applied by rebuilding from the start path; the API's report is a new error code)
  1. Server: read `X-Client-Version`, sanitise it (length and characters bounded, never rejected) and put it in the request's log scope as
     `ClientVersion`, so every line of the request carries it. Integration tests: present, absent, malformed or overlong.
  2. Server + contract: the error `UNSUPPORTED_CLIENT_VERSION` (HTTP 426) in the catalogue with its mapping test, and in `05`'s error table.
     The server does not emit it yet (rejecting versions is a later task). Client: `ApiErrorCodes`, `FeedbackMessages`, `ClientErrorCodesTests`.
  3. Client: send `X-Client-Version: AppInfo.Version` on every request (`ApiTransportRequest`, `UnityWebRequestTransport`, `ApiClient`). Tests on the request.
  4. Client: `ConnectionMonitor` on a snapshot of another `contentVersion`: refetch `/content` through `ContentService` first, and apply the snapshot
     only after the new content is loaded and matches it; a failed or still different refetch is `IncompatibleVersion` and applies nothing.
     `UNSUPPORTED_CLIENT_VERSION` on any request is `IncompatibleVersion`. Tests for the refetch-then-apply order (the fake transport records the order).
  5. `GameRoot`: on a changed content, rebuild the content-bound parts (HUD, build menu, placement, inspector, research, welcome-back, display city,
     prediction watch, monitor) through the same code as the first connect, then apply the snapshot.
  6. Docs per Docs impact, `CHANGELOG`, full checks, `/finish-task`.
- **Done:** write-ahead; step 1 (server logs `X-Client-Version`: `ClientVersionHeader`, 15 tests, docs); step 2 (error code `UNSUPPORTED_CLIENT_VERSION`: catalogue, `05`, client constant and message, counts; the Unity side is not compiled or run yet, that happens with step 3).
- **Step 3 done:** `ApiClient` (optional `clientVersion`, default `AppInfo.Version`), `ApiTransportRequest.ClientVersion`, `UnityWebRequestTransport`; 5 new Unity tests. First Unity run of the task, which also compiled step 2: EditMode 952/952, PlayMode 165/165.

## Decisions
<!-- Every decision, when it is made, including small ones. Scope: local | project-wide (→ 12-decisions.md row) | architectural (→ ADR). -->
| # | Decision | Alternatives considered | Why | Scope |
|---|---|---|---|---|
| 1 | New content is applied by rebuilding the content-bound parts through the start path (owner's choice A) | A live content holder read by ~25 classes; refetch and verify only, content used after a restart | Reuses the code that already builds everything from a `GameContent`; no class has to know about swapping | local |
| 2 | The API reports an incompatible client with a new error code `UNSUPPORTED_CLIENT_VERSION` (HTTP 426), which the server does not emit yet (owner's choice) | No new code: only the existing contract-mismatch case | The spec says the API "reports" it, and the later rejection task then has a code ready | project-wide (→ `12-decisions.md` row at finish) |
| 4 | The code is `UNSUPPORTED_CLIENT_VERSION`, not `CLIENT_VERSION_UNSUPPORTED` | The first name | `ClientErrorCodesTests` treats every `CLIENT_` code as client-only (the three failures before an answer exists), so a server code with that prefix would break its split | local (name of decision 2) |
| 5 | The guard test `EveryCode_HasASourceThatProducesIt` gets a `_reservedCodes` list for codes defined before anything produces them; a second test fails if a reserved code is already produced | A config key that makes the server refuse old builds (scope: spec says not now); a client-only code | Owner chose it (asked in session 1, G-Tests: loosening a test) | local |
| 3 | The client version is logged as a log scope value (every line of the request), not as a line of its own; sanitised to 32 characters of `[A-Za-z0-9.+_-]`, else `invalid`; absent is `none`; nothing is refused | One new log event (id) per request; logging the raw header; rejecting now (spec: not now) | A scope gives every line the build without a new event and without extra volume; the raw header is client-controlled text (log forging) | local |
