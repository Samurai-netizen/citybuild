## Decisions
<!-- Every decision, when it is made, including small ones. Scope: local | project-wide (→ 12-decisions.md row) | architectural (→ ADR). -->
| # | Decision | Alternatives considered | Why | Scope |
|---|---|---|---|---|
| 1 | Placeholder looks are a code table (`BuildingLooks`), not a ScriptableObject | ScriptableObject asset | The spec allows either; an asset needs the Editor or hand-written YAML (`09` AI-friendly rule 4), a code table is diffable and testable | local |
| 2 | `server-panel/` is committed in this PR, with a comment added above `say()` in `panel.sh` | Leave it untracked and move it away | The owner's answer "add it to the pr"; the docs check scans untracked files, so it could not stay as it was | local |
| 3 | The look is chosen by the **city's era**, not the building type's own era; a type without a look for that era keeps its latest earlier one, an unknown type gets a grey fallback box | Use `BuildingDefinition.Era` | "so later eras can add looks": the same Cottage can look different in Era II; the fallback keeps content newer than the client drawable. A view remembers its era and gets a new body when the city's era changes | local |
| 4 | A building under construction is drawn as a low foundation (25 % height); an upgrading one keeps its current level's height; the new level shows only when the server's state says so | Draw every building finished | `09` UX rules: never spawn a finished building before the server confirms | local |
| 5 | Level height is the body object's y scale in whole permille (`BuildingLooks.HeightPermille`: 1000 + 200 per level above 1) | Per-part sizes; a float factor | One rule for every look, integers like the rest of the game maths, no look data repeated per level. Turned parts (roof, awning, wheel) are stretched with the body, which is fine for placeholder art | local |
| 6 | `PlaceholderArt` (`CreateMaterial`, `Destroy`) is shared by `GroundTiles` and the new factory; `GroundTiles` lost its two private copies | Copy the helpers into the factory | Removes real duplication; behaviour unchanged (its tests pass) | local |
| 7 | `CityView.Show` runs on every `DisplayCity.Changed` (once a second): it keeps a reusable id set and list, so a call where nothing changed allocates nothing | Diff only on a new snapshot | Prediction changes phases (a construction ends) between snapshots, so the views must follow the display city | local |
| 8 | Unity ran in a mirror project again (the owner's Editor holds the lock): `cp -Rc` of the project, `shared` symlinked beside it so the manifest's `file:../../../shared/Simulation` still resolves; the new `.meta` files were copied back | Ask the owner to close the Editor | Same reason as M0-43 decision 5 | local |
