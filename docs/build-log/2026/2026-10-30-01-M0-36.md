| # | Decision | Alternatives considered | Why | Scope |

| 1 | The frozen `content-golden-v1.json` is linked from `CityBuilder.Simulation.Tests/Fixtures/` into the integration tests' output (`None Link`), and the server loads it through `Content:FilePath` | A copy in `IntegrationTests`; a path to the source tree (`RepositoryPaths`) | One frozen file for both golden tests, so they can't drift apart; the fixture is protected (`15`) and stays untouched | local |
| 2 | Four tests, each playing the session on its own database through one walk (`PlayAsync`: the clock moved to every action and row time, the commands, then the check), one behaviour each: rows, stored city, ledger, one worker | One long test checking everything at every row | One behaviour per test (`.claude/rules/tests.md`); the walk is ~15 requests, so four runs cost ~1 s | local |
| 3 | The rows are written out as text (the engine test's hand-checked values), not computed; in addition the stored city is compared field by field (`SampleCities.Describe`) with an engine replay of the same script | Only the table's numbers; comparing the snapshot JSON with an engine city mapped by `CitySnapshotMapper` | The table is the independent expectation; the replay adds what the table leaves out (timers, labor, segments, settled second, completion second). The mapper needs a `Settlement`, whose constructor is internal: no production change just for a test | local |
| 4 | The replay is a short copy of the engine test's script in `GoldenScenario1Http`, next to the HTTP version of the same script | Referencing `CityBuilder.Simulation.Tests` (its script is internal) | A test project referencing another test project pulls in its fixtures and runner; the two scripts are a few lines each and sit side by side | local |
| 5 | The player acts with the token the dev login returned, not one from the server's `AccessTokens` | `ApiClient` (issues its own token) | The task says dev-login → …; this is the client's real path | local |
| 6 | One worker: two players in one database play in step on the shared clock; at 1170 one sets the post (id 5) to 1 worker; an hour later earnings differ by ≤ 10, the 2-worker one earns 290–310 (the table's +10 per 120 s), the 1-worker city has one more free worker | Two separate tests compared through constants | Same clock and same requests, so the only difference is the assignment; the 290–310 bound makes the "same earnings" claim meaningful (both 0 would also be within 10) | local |
| 7 | `05` unchanged: nothing differed | — | Every row, the stored city and the ledger matched on the first run | local |
