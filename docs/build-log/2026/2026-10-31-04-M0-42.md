## Problems and surprises
- The owner's user-secrets hold `ConnectionStrings:CityBuilder` but not `Auth:SigningKey`, so the first step of the check stops with a clear message. It is a setup step that `docs/getting-started.md` already names, not a code defect. `LOCAL-E2E.md` now checks it first, and Troubleshooting has the row.
- In the owner's run the label showed "Connected" and "Offline" together. Likely cause, read from the files and not proven by a test: the scene has no camera and `PanelSettings.asset` has `m_ClearColor: 0`, so nothing clears the screen, and the label's background has alpha 0.65 (`ConnectionStatus.uss`). The old text shows through and past the shorter new label. The API's log has no pair of `GET /city` at the same moment (five settles, 12 to 24 s apart), so a second `GameRoot` is unlikely.
- Those gaps are shorter than the 120 s interval, which fits a poll on each return to the Editor (`OnApplicationPause(false)`). The Editor's own log doesn't show it, so this is read from the API's log only.
- `Run In Background` is off (`ProjectSettings.asset`), so the game doesn't run while the owner is in a terminal. That is why the steps say to click back to the Game view. The headless run can't show this: batch mode runs regardless.
