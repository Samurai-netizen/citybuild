- **What exists** (read first): the error mapping lives in three places that each build Problem Details by hand: `CommandResponses` (engine codes,
  `IDEMPOTENCY_CONFLICT`, `INVALID_ARGUMENT`), `BearerChallenge` (401), `RequestBodyLimit` and `AuthEndpoints` (400); a body that doesn't bind
  gets the framework's empty 400 (in Development the exception page, which echoes the request headers, the bearer token included: M0-32
  follow-up); an unexpected exception is an empty 500; `ConcurrencyConflictException` is not mapped; no rate limiter.
- **Plan:**
  1. **The catalogue:** `Api/Errors/` = `ApiError` (the renamed `CommandError`), `ErrorCatalogue` (one member per code of `05` + `All` + the engine
     mapping `Of(MutationErrorCode)`), `ApiProblem` (the one place that writes Problem Details: `type`, `title`, `status`, `detail`, `code`, `requestId` when
     present; `traceId` from the framework). `CommandResponses`, `BearerChallenge`, `RequestBodyLimit`, `AuthEndpoints` use it. Tests (table-driven, over
     HTTP): every catalogue code ↔ status ↔ exact shape; a test fails when a code is in the catalogue and not in the table, or in the table and not in
     the catalogue, or when no source produces it.
  2. **The global handler:** `UseExceptionHandler` with an `IExceptionHandler`: `ConcurrencyConflictException` → 409 `CONCURRENCY_CONFLICT`, a body
     that doesn't bind (`BadHttpRequestException`, thrown in every environment: `RouteHandlerOptions.ThrowOnBadRequest`) → 400 `INVALID_ARGUMENT`,
     anything else → 500 `INTERNAL_ERROR` (the exception's text in Development only, never a stack trace); `UseStatusCodePages` gives the empty
     404/405/415 answers a Problem Details body. The command endpoints answer a conflict with the request id. Tests: each exception type, the
     bearer token never echoed in Development, no exception text in Production, a valid token without a city → 500, a lock timeout on PostgreSQL → 409.
  3. **Rate limits:** `RateLimits` options (validated on start), a chained partitioned limiter (fixed windows) keyed by player id (commands: burst per second
     and per minute; `GET /city`) and by IP (dev login), endpoints marked with their class, `OnRejected` = 429 `RATE_LIMITED` + `Retry-After`.
     The test factories get limits far above any test's pace, so other suites are unaffected; the rate-limit suites derive servers with real or small limits.
     Tests: burst → 429 with `Retry-After`; normal polling never limited; one player's spam doesn't block another; dev login per IP;
     rejected before the binding and the lock; defaults are 05's numbers.
  4. **Input limits:** the 4 KB limit exists since M0-30; here its remaining gap closes (Kestrel stopping a chunked body → the handler's 400 `INVALID_ARGUMENT`)
     and the Problem Details of the binding failures get a code. Tests with the above.
  5. **Docs and finish:** `05`, `07`, the module docs, the how-to, ADR As-built lines, getting-started, testing README, decision rows, CHANGELOG,
     the rest of Docs impact; Definition of Done; self-review (security: line by line); the real server by hand as `devtest` (OD-14); PR.

## Decisions
<!-- Every decision, when it is made, including small ones. Scope: local | project-wide (→ 12-decisions.md row) | architectural (→ ADR). -->
| # | Decision | Alternatives considered | Why | Scope |
|---|---|---|---|---|
| 1 | The catalogue is code in `Api/Errors/`: one `ApiError` per code of `05`'s table, `ErrorCatalogue.All` lists them, every writer of Problem Details goes through `ApiProblem` | Keep `CommandResponses.Of` and add the other codes beside it; generate the catalogue from `05` | One place for code ↔ status ↔ title, so a new code is one row plus one test row (recipe "New error code"); `05` stays prose until DocTools (M0-61) generates it | local |
| 2 | A body that doesn't bind is a `BadHttpRequestException` in every environment (`ThrowOnBadRequest = true`) and the handler answers 400 `INVALID_ARGUMENT` | Leave the framework's answer (empty 400, the developer exception page in Development) | The code is missing from the framework's answer and Development's page echoes the bearer token (M0-32 follow-up) | local |
| 3 | Statuses the catalogue has no code for (404 no route, 405, 415) get a Problem Details body from `UseStatusCodePages` with `status`, `title`, `traceId` and **no `code`**; no new codes | New codes `NOT_FOUND`, `METHOD_NOT_ALLOWED`, `UNSUPPORTED_MEDIA_TYPE` (an additive change of `05`'s table) | A new code is the owner's contract to extend, and a client has no use of one for a transport mistake; adding them later is one row each. **Open question for the owner** | local, open |
| 4 | No stack trace in any response, in any environment; Development adds the exception's type and message to `detail` | Stack trace in Development (the task's wording "outside Development") | `05` says "no stack traces in responses"; the logs have them; the stricter reading satisfies both | local |
| 5 | The rate limiter is the framework's, one chained `GlobalLimiter` of fixed-window limiters that pick their partition from endpoint metadata (`RateLimitMetadata`, set on groups and routes) | Named policies (`RequireRateLimiting`), which allow one limiter per policy, so the two windows of "10/s, 120/min" would need a custom limiter; a token bucket (10 tokens, 2 per second), which is not the contract's two windows | `PartitionedRateLimiter.CreateChained` gives both windows with no custom limiter type; the metadata lets a test list every endpoint's class | local |
| 6 | `GET /content` is not limited (05 lists three limits) | A fourth limit | Follow-up for the owner: it reads no database; a heavy loop costs only CPU | local, open |
| 7 | An unexpected exception is logged by the handler itself (`ErrorLog.UnhandledException`, Error, with the exception); a conflict and a bad body are not logged here | Leave the framework's logging on (`SuppressDiagnosticsCallback`) for every handled exception | .NET 10 logs nothing for an exception an `IExceptionHandler` answers (a probe showed only startup lines), so without this an `INTERNAL_ERROR` would leave no trace; logging every 400 as an Error with a stack would let a client fill the log. Conflict logging is M0-35's | local |
