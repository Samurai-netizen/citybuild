## Problems and surprises
- A placeholder helper (`throw new NotImplementedException()`) was written in the first draft of `CommandConcurrencyDatabaseTests` and
  replaced before the first build by `DatabaseCommands.ReceiptLine`, the one format `StoredAsync` also uses.
- Without the receipt lookup under the lock, a sequential replay still answers correctly: the unique key and the recovery act as a
  backstop (the transaction rolls back whole). The lookup's own effect shows where a mutation would be rejected (a conflict on another
  command would then commit a settlement); the Application tests pin the lookup itself (`CommandPipelineTests`, step order).
