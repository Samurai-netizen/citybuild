### Session 1 — 2026-10-26 · Claude Code / claude-opus-5-5
- **Model:** `[O]` task on Opus 5.5, as `11` asks.
- **Plan** (each step ends green and is checkpointed):
  1. **Application:** `ICityTransactionRunner.RunAsync(playerId, work)`, the one entry point that loads a city for change: it begins the
     transaction (`IUnitOfWork.BeginTransactionAsync`), loads the acting player's city under the row lock, hands the work a
     `CityTransaction` (the locked city and `SaveAsync(ledger, receipt)`, once), and commits when the work returns; an exception rolls
     everything back. A runner (scoped, one per request) runs once, so no request locks a second city. `ConcurrencyConflictException` for a
     lock timeout or a version mismatch (the API maps it to `CONCURRENCY_CONFLICT`, M0-26/M0-34). `SettleCity` moves onto the runner.
     Fast tests with fakes: commit after the work, rollback on an exception, one run per runner, one save per transaction; an architecture
     test that only the runner depends on `ICityRepository`.
  2. **Infrastructure:** `LoadForUpdateAsync` runs `SELECT … FOR UPDATE` and refuses to run outside a transaction or for a second city in
     the same context; `BeginTransactionAsync` sets `lock_timeout` for the transaction from `Database:LockTimeoutMilliseconds` (default 3000);
     a lock timeout (SQLSTATE `55P03`) and EF's concurrency exception become `ConcurrencyConflictException`. The runner is registered.
     Integration tests: an exception after the writes rolls back everything; a version mismatch is detected and rolled back; two
     transactions on one city serialize (the second sees the first's committed state); a lock wait beyond the timeout is a conflict; a
     second city can't be locked in one request. The existing database tests go through a transaction (their assertions stay).
  3. **Docs:** `06` (built so far, the runner), `03` if the lifecycle wording changes, getting-started (the new key), module docs
     Application, Infrastructure, Api, `docs/testing/README.md`, decision row, `CHANGELOG.md`; the rest per Docs impact.
