## Problems and surprises
- A build with `-p:TreatWarningsAsErrors=false` followed by a normal build said "0 Warning(s)": the second build was incremental, and
  the property is not an input of the compile step. Checking warnings-as-errors needs `--no-incremental` (as M0-02 did).
- A mutation of the target framework "survived" because `perl s///` without `/g` replaced the first `netstandard2.1`, which sits in the
  csproj comment. A flawed mutation, not a test gap: with the element targeted, `Assembly_IsBuiltForNetStandard21` kills it. The same run
  showed that `GenerateDocumentationFile=false` never reaches the tests: the compiler stops the build first (IDE0005 needs the doc file).
- The first review run failed for an environment reason, not a code reason: four of five reviewers died with `API Error: 403 Request not
  allowed` / `authentication_failed` (a credentials problem around the owner's `/login`), and the fifth ran for 75 minutes. The rerun was
  paused once and resumed from its journal (finished agents replay from cache).
- The owner's Unity project appeared untracked in `client/CityBuilder/` (37,937 generated files, no `.gitignore` yet). `check-docs.sh`
  scans untracked files, so the pre-commit hook would have rejected every commit (decision 24). `core-instructions/09` lists `*.sln`,
  but Unity 6.3 writes `CityBuilder.slnx`: M0-04's `.gitignore` has to cover it as well.
- The mutation script's first reset used `rsync -a`, which keeps old modification times: MSBuild would then have reused a mutated build
  output. It now resets with `rsync -rl --checksum` (restored files get a new time), like the earlier scripts that used `cp`.
