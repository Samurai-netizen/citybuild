| 4 | The shared csproj sets `AnalysisLevel=latest-recommended` and `EnforceCodeStyleInBuild=true` in addition to the properties the task lists | Only the listed properties | `14` requires both, and the project sits outside `server/`, so it inherits nothing from `server/Directory.Build.props`. Probe B: with them the build itself reports IDE0005, IDE0011, CS1591 and CA1036, so build, `dotnet format` and CI give one verdict (the lesson of M0-02 decision 20) | project-wide (shared-engine build convention → `12` row at the docs step) |
| 5 | The shared csproj does not opt in to lock files, and there is no `packages.lock.json` for it | `RestorePackagesWithLockFile=true` with a committed lock file | Probe A: `dotnet restore --locked-mode` passes for the project without a lock file, and an opt-in lock file would only say `{"dependencies": {".NETStandard,Version=v2.1": {}}}`. The engine may never have packages (BCL only; a package needs G-Dependency and fails the architecture test), so the file would pin nothing. Answers the M0-02 follow-up | local |
| 6 | `ItemId` implements `IComparable<ItemId>` and defines `<`, `<=`, `>`, `>=` plus `==`, `!=`, each operator with an XML doc | No `IComparable` (sort through a comparer); suppress CA1036 | The task asks for ordinal comparison. Probe B: once a type implements `IComparable`, CA1036 demands the four relational operators and CS1591 their docs, and under warnings-as-errors both fail the build. A suppression would need a justification and a log line for no gain | local |
| 7 | The helpers are the static class `IntegerMath` in the namespace `CityBuilder.Simulation` (`Runtime/IntegerMath.cs`); parameters are named `dividend`/`divisor` instead of the rule file's `a`/`b` | `Calc`, `IntMath`, `Durations`; a `Numerics` or `Math` namespace | One short, glossary-style name for "the only division"; the rule file only fixes the shape (`a ≥ 0, b > 0`). A namespace named `Math` would hide `System.Math` inside `CityBuilder.Simulation.*`, and `Numerics` would shadow `System.Numerics`. M0-05's Unity test calls `IntegerMath.CeilDiv` | local |
| 8 | Arguments outside the contract (negative dividend, divisor ≤ 0, negative labor, permille outside 0 to 1000) throw `ArgumentOutOfRangeException` with the parameter name | Return an error result; clamp; assert only | `14`: exceptions are for programmer errors, results for business rules. Content validation and the mutation entry points check inputs first (`04` §9), so a bad value here is a bug; clamping would hide it | local |
| 9 | `ApplyPermilleReduction` splits the labor into whole thousands and a rest (`q × m + CeilDiv(r × m, 1000)`), so it is exact for every non-negative labor and cannot overflow | `CeilDiv(checked(labor × (1000 − permille)), 1000)` (one line, throws `OverflowException` above about 9.2e15 labor) | A helper that is total on its domain cannot turn a bad content value into a crash in every settlement of a city; the rest of the arithmetic still sits in `checked(...)`. Proved by tests: an exhaustive small range, and `BigInteger` references up to `long.MaxValue` | local |
| 10 | `IntegerMath.PermilleScale = 1000` is a public named constant | A literal 1000 in code | `14`: no magic numbers. The unit "permille" is a definition, not a game number, so it does not belong in content | local |
| 11 | `ItemId` wraps non-empty text: the constructor throws for null and empty, `default(ItemId)` is the empty id (equals only itself, sorts first), there is no format check, `GetHashCode` is the string's own hash | Check lowercase snake_case in the struct; a deterministic custom hash; a class instead of a struct | The task asks for a readonly struct with ordinal comparison. Id format is content validation's job (M0-07); the struct only guards against a missing value. The string hash varies between processes, which is harmless because no engine code may depend on `Dictionary` or `HashSet` order (`04` §9) | local |
| 12 | The Simulation tests use integers only, with `BigInteger` for exact reference values, and exhaustive ranges instead of random cases (CeilDiv 0..400 × 1..70, reduction 0..1500 × 0..1000) | `double` oracles; seeded random cases | `.claude/rules/simulation.md` applies to this test project too (no `float`, `double`, `decimal`). Exhaustive ranges need no seed and cover every rounding boundary | local |
