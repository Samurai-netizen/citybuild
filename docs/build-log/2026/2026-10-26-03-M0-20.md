     constructor; Domain tests for the rules.
  2. **Application ports:** `ICityRepository` (`LoadForUpdateAsync(playerId)`, `Save(city, ledger, receipt)`: stages the writes),
     `IUnitOfWork` (`SaveChangesAsync`: writes what was staged), `IPlayerRepository` (find by dev name, add). `CityAggregate` gets what
     persistence needs: city id, state version, content version and the completion clock of each completed research (decision 2),
     recorded by a new `CityAggregate.Advance` that `SettleCity` uses. Application tests updated (fakes for both ports).
  3. **Mapping (Infrastructure, pure):** `CityMapping`: `CityAggregate` ↔ `CityRow` + inventory, building and research rows. Building
     columns are null exactly when the phase doesn't use them (decision 3); load checks that and fails loudly on a broken row. Derived
     values (reserved outputs, stall reasons, workers provided/free, effective caps and labor) are never stored. Round-trip tests without a
     database: every phase, a frozen cycle (null end), a cycle started at clock 0, active and completed research, era, inventory; and
     each broken-row case.
  4. **Repositories (Infrastructure):** `CityRepository`, `PlayerRepository`, `UnitOfWork` over `CityBuilderDbContext`, registered in
     `AddCityBuilderPersistence`. `Save` merges the mapped rows into the tracked ones (insert for a new city), adds ledger rows and the
     receipt, stamps wall times from `TimeProvider`, writes `state_version + 1`. Fast tests on EF's change tracker (no database); the
     database tests are M0-21, the row lock M0-22.
  5. **Docs:** module docs Domain, Application, Infrastructure; `06` (built so far, the mapping rules); `03` ports; architecture overview;
     `CHANGELOG.md`; the rest per Docs impact.
