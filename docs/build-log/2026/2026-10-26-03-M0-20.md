| 2 | `city_research.completed_at` comes from `CityAggregate`, which keeps the completion clock of every completed research: loaded from the rows, and recorded by `CityAggregate.Advance` (the clock is the `EndsAt` of the research that was running, as the engine's research timer fires exactly then). Saving a completed research without a clock throws | the engine keeps the clock in `CityState` (an engine and `04` change, the client too); make `completed_at` nullable or drop it (G-Contract on `06`); the repository guesses from the loaded `research_ends_at` | no contract or engine change; the clock is exact, not guessed; a city advanced around the aggregate fails loudly instead of storing a wrong clock | local |
| 3 | `city_buildings` nullable columns are null exactly when the building's phase doesn't use them: Constructing → start, end; Upgrading → start, end, target level; Idle → none; Producing → start, cycle labor, labor remaining, segment start, and the end unless frozen. The engine's 0 for an unused field ↔ null | "0 means null" | a cycle can start at clock 0, so 0 is a real value; the phase decides, and load rejects a row that breaks the rule | local |
| 4 | Inventory: the engine drops items at 0, so an existing row of an item no longer in the state is set to 0, never deleted; load ignores 0 rows | delete the row | `06` writes inventory as an upsert; a 0 row is harmless and keeps the item's history in one place | local |
| 5 | Domain types in feature folders (`Players/`, `Ledger/`, `Commands/`), immutable, validated in the constructor; the city or player they belong to and the wall time are not part of them, the repository adds those when it stores them | carry `CityId`, `CreatedAt` | the use case writes them for the city it holds; one clock (`TimeProvider`) stamps every row of a save | local |
| 6 | `LedgerReason` is an enum; Infrastructure maps each value to the text of `06` explicitly | string constants | a typo can't reach the database; the mapping lists every reason in one place | local |
| 7 | `LedgerEntry` rules: delta ≠ 0, quantity after and before ≥ 0, reference type and id both set (not blank) or both null; `CommandReceipt`: hash exactly 32 bytes | no checks (the database has none for these) | a wrong row in an audit trail is never fixed later; fail when it is made | local |
| 8 | `ICityRepository.Save` and `IPlayerRepository.Add` are synchronous and only stage; `IUnitOfWork.SaveChangesAsync` writes everything at once | `SaveAsync` that writes at once (the skeleton) | the task asks for a unit of work; one write per request is what M0-22 wraps in the transaction | local |
| 9 | `Save` takes the ledger entries and the receipt of the change; a city the repository didn't load is new and is inserted (the first login, M0-25) | a separate `Add(city)` | the task's signature; one way to store a city | local |
| 10 | `CityAggregate.ContentVersion` keeps the loaded value; setting it on settle is M0-23's, with the rest of the settle | set it in `MarkSettled` now | keeps the change inside this task; nothing reads it before M0-23 | local |
| 11 | `city_buildings.phase` text is the API's spelling (`Constructing`, `Upgrading`, `Idle`, `Producing`, `05`), mapped by an explicit switch, compared exactly on load | the enum's numeric value; snake_case text | one spelling for the same thing in the API and the database; readable in `psql` | local |
| 12 | A row that breaks a rule (columns against the phase, an unknown phase, a partial running research, a child row of another city, anything the engine's constructors reject) fails the load with `InvalidOperationException` naming the city; the engine's `ArgumentException` is the inner exception | repair or skip the row | a broken city must never be settled and saved over; loud and early | local |
| 13 | `Save` merges the mapped rows into the tracked ones with `CurrentValues.SetValues`, so EF writes only changed columns; a city the context doesn't track is new and inserted | delete and reinsert the children; attach and mark everything modified | minimal writes, and `state_version` stays EF's original value for the concurrency check | local |
| 14 | Every `Save` writes `state_version = loaded + 1`, a new city too (stored as 1 when created with 0) | write the version only when something changed | one rule now; "+1 only if anything changed" is M0-23's (its spec) | local |
| 15 | Wall times (`created_at`, `updated_at`, ledger and receipt `created_at`) from one `TimeProvider` reading per save; `created_at` of a loaded city is kept | `now()` defaults in the database | principle 3 (server time only from `TimeProvider`); testable with a fixed clock | local |
