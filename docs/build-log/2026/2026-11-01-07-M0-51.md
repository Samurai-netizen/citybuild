### Session 2 — 2026-11-01 · Claude Code / claude-sonnet-5-5
- **Why:** owner feedback on PR #71 in chat: "One menu should close automatically when the other is opened - for all menus" (Owner input below).
- **Plan:**
  1. **A rule, not two special cases.** `MenuGroup` (`Presentation/Ui/`): each menu joins with a `close` action and gets a member; `NotifyOpened()` on a member calls the `close` of every other member. Menus raise an `Opened` event when they go from closed to open: `BuildMenu` (the sheet) and `BuildingInspector` (hidden to shown; a new model for an already shown panel is not an opening). `GameRoot` makes the one group and joins both; the research screen (M0-52) and later menus join the same group.
  2. **Close actions that cannot hurt.** The sheet closes with `SetOpen(false)`; the inspector closes by dropping the tile, but only when it is shown (a placement flow in progress owns the tile: dropping it would lose the player's pick).
  3. **Tests:** EditMode `MenuGroupTests`; PlayMode: opening the sheet closes the inspector and opening the inspector closes the sheet; the placement tile is kept.
  4. **Docs and the directive:** OD-16 in `15` (protected: the edit asks the owner), the rule in `09` and a checklist line in `add-ui-screen.md`, the module doc, the [MANUAL] look, CHANGELOG.
- **Done:** write-ahead. `MenuGroup` (`Ui/`), `BuildMenu.Opened` and `BuildingInspector.Opened`, `InspectorFlow.Close`, `GameRoot` joins both menus; OD-16 in `15` (the owner approved the protected-file edit by the permission prompt). Tests: `MenuGroupTests` (EditMode, 5), and four more in `InspectorFlowTests` (PlayMode, now with a real `BuildMenu` joined as `GameRoot` does): opening the sheet closes the inspector, opening the inspector closes the sheet, a refresh or another building is not an opening, opening the sheet while placing keeps the placement's tile.
