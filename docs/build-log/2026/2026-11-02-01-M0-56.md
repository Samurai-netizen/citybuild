## Decisions
<!-- Every decision, when it is made, including small ones. Scope: local | project-wide (→ 12-decisions.md row) | architectural (→ ADR). -->
| # | Decision | Alternatives considered | Why | Scope |
|---|---|---|---|---|
| 1 | The lost response is a new class, `LostResponseDatabaseTests`, with a `GET /city` between the lost response and the retry | Adding to the three existing `Post_SameRequestAgain_…` tests | Those retry a city that has not moved. A client that heard nothing polls first, so the retry arrives with the city past the response's version: the replay must still give the old bytes and store nothing | local |
| 2 | "Discard the response" is played by the test: it keeps the first answer only to compare it | A handler that drops the bytes on the wire | The server can't tell the difference once it has written its answer; the comparison needs the bytes | local |
| 3 | One extra test: the client hangs up while the request waits for the city's lock, and it accepts either end of the first request | Not testing a hang-up; asserting that it rolled back | Not in the spec's list, but it is the other way a response gets lost, and it is one small test. The contract is "counts once", so the test states that, not how | local |
| 4 | The client's fake is a small wire of its own inside the test, `ReceiptServer`, that keeps receipts by request id | Queuing `.TimeOut().Answer(...)` on `FakeTransport` | A queue would answer the fixture whatever id the retry carried, so a retry with a new id would pass. With receipts, a new id counts as a second application and fails the test. It stays private to the test: `FakeTransport` remains the only shared fake | local |
| 5 | One extra client test: a poll in the wait before the retry | Only the spec's case | The replay is older than what a poll has shown; the store must keep the newer city. The behaviour exists (`IsNewerThan`), and nothing tested it in this order | local |
| 6 | The manual check is a script with a page, both in `docs/testing/`, not steps to paste | Commands to paste in a terminal; a script in `scripts/dev/` | The spec names `docs/testing/`, and a timing-dependent kill is not something to do by hand. Not in `AGENTS.md`'s command list: that file is protected and the check is occasional, so the testing README lists it | local |
| 7 | Many players with one command each, killed at the first answers; the script says so (exit 3) when no command fell between commit and answer | One player and one command; a fixed sleep before the kill | The window is milliseconds. A 5 ms gap between commands caught nothing in 3 runs, no gap killed before anything arrived in 4 runs. Waiting for the first answers caught one in 5 of 5. A clean run that proved nothing must not read as a pass | local |
| 8 | The check starts the built program from its build folder on port 8090, with the dev login's limit raised by an environment variable | `dotnet run`; stopping the server on 8080 | A kill of `dotnet run` leaves its child alive. The owner's running server is not mine to stop. The dev login allows 10 per minute per address, and the check needs 61 | local |
| 9 | `--clean` removes only `killcheck-*` players, in a transaction | Leaving them; a new dev database | The rows are the check's own, and every run adds 61 | local |
