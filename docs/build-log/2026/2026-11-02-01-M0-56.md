## Decisions
<!-- Every decision, when it is made, including small ones. Scope: local | project-wide (→ 12-decisions.md row) | architectural (→ ADR). -->
| # | Decision | Alternatives considered | Why | Scope |
|---|---|---|---|---|
| 1 | The lost response is a new class, `LostResponseDatabaseTests`, with a `GET /city` between the lost response and the retry | Adding to the three existing `Post_SameRequestAgain_…` tests | Those retry a city that has not moved. A client that heard nothing polls first, so the retry arrives with the city past the response's version: the replay must still give the old bytes and store nothing | local |
| 2 | "Discard the response" is played by the test: it keeps the first answer only to compare it | A handler that drops the bytes on the wire | The server can't tell the difference once it has written its answer; the comparison needs the bytes | local |
| 3 | One extra test: the client hangs up while the request waits for the city's lock, and it accepts either end of the first request | Not testing a hang-up; asserting that it rolled back | Not in the spec's list, but it is the other way a response gets lost, and it is one small test. The contract is "counts once", so the test states that, not how | local |
