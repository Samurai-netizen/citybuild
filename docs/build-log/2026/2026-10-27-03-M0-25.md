### Session 1 — 2026-10-27 · Claude Code / claude-opus-5-5
- **Start:** PR #36 (M0-24) is merged (`222446d`), so the branch starts from `main`; M0-24's board row goes to `Done` with this task. The
  task is `[S]`; this session runs on Opus 5.5, the owner's session model (a stronger model than the tag asks for).
- **Plan:**
  1. **Tokens:** `Auth` options (signing key from user-secrets or the environment, at least 32 bytes; token lifetime, default 12 h;
     `DevLoginEnabled`, which stops the start outside Development), JWT bearer validation (HS256 only, issuer, audience, no clock skew,
     lifetime checked against the server's `TimeProvider`), an access token issuer, `ICurrentPlayer` (Application port) resolved from the
     token's `sub` claim (Api), and every endpoint requiring a token unless it opts out (`/health`, OpenAPI, dev login). Tests over HTTP
     with a test-only endpoint: valid, missing, malformed, expired, wrong-signature (and unsigned) tokens; startup guards (missing or short
     key, dev login enabled outside Development).
  2. **First login:** `DevLogin` use case: the player by name, or, in one transaction, a new player, the starter city
     (`CityFactory.CreateStarterCity`) and its `STARTING_GRANT` ledger rows; the city insert is the one write without a city lock
     (ADR-0009), through a narrow port, not `ICityRepository`; two first logins of one name racing → the loser reads the winner's player.
     `POST /api/v1/auth/dev-login` mapped only in Development with dev login enabled. Tests on PostgreSQL: first login rows and a ledger that
     reconciles, the same name → the same player and no second city, the race, the token works; Production → 404.
  3. **Docs and finish:** `05`, `06`, `07`, module docs, getting-started (configuration, the signing key secret), testing README, overview,
     decision row, `CHANGELOG`; Definition of Done, self-review, PR.
