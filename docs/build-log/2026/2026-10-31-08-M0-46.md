## Decisions
<!-- Every decision, when it is made, including small ones. Scope: local | project-wide (→ 12-decisions.md row) | architectural (→ ADR). -->
| # | Decision | Alternatives considered | Why | Scope |
|---|---|---|---|---|
| 1 | The flow's states: `Idle` (no card), `PickingTile` (card, no tile), `Confirming` (card and tile), `Sending` (the intent is on its way). A tile is picked with a tap on the ground (`TileSelection`), **Place** confirms | A confirm dialog; place on the second tap of the same tile | `TileSelection.Tap` already toggles the same tile off, so a second tap cannot be the confirm; a bar with Place and Cancel is the spec's "confirm" and also holds the hint and the error | local |
| 2 | Tile hints (green free / red occupied) come from `DisplayCity.Current` (as the cards do, M0-45 decision 8); an occupied tile can still be picked and confirmed, with the hint "Tile is occupied": hints never block, the server decides (`09` UX rules, M0-45 decision 6) | Refuse a tap on a red tile | Same principle as the cards. Buildings only change with a snapshot, so the display city and the raw snapshot agree on occupancy | local; owner may prefer to refuse red taps |
| 3 | The ghost is drawn from `CommandSender.Pending` (the `PlaceBuilding` intents), not from the flow's own state | The flow keeps its own ghost | The sender is what knows the request is open (retries included) and drops the intent in the same call that applies the snapshot, so there is no frame with both a ghost and the building, or neither | local |
| 4 | Success ends the flow (card deselected); a failure keeps the card, drops the tile and shows the error; **Cancel** ends the flow in any state but `Sending` | Keep the card after a success (build many); cancel a sent command | The spec says the real building appears and a failure shows the error; a sent command may already be applied, so hiding its result would lie | local |
| 6 | Unity ran in a mirror project again (the owner's Editor holds the lock, PID seen with `lsof`): `scratchpad/run-unity.sh` clones the project once, rsyncs `Assets`, `Packages` and `ProjectSettings` in, runs the tests and copies back the `.meta` files the repo lacks | Ask the owner to close the Editor | Same reason as M0-44 decision 8 and M0-45 decision 14 | local |
| 7 | The ghost's material is the primitive's default (URP Lit) material switched to a transparent surface at runtime (`_Surface`, blend, no depth write, `_SURFACE_TYPE_TRANSPARENT`, queue 3000), alpha 0.5; the ghost is the finished level 1 look | A material asset in `Resources`; a custom unlit shader; the foundation look | No shader lookup by name and no YAML to hand-write (`09` rule 3); the finished look tells the player what they ordered. Risk: a device build could strip the transparent variant (see Follow-ups) | local |
| 8 | A render test proves the translucency on screen (tile bare / ghost / finished building, mean colour in the tile's rectangle); `ControllableTransport` (PlayMode) answers requests when the test says, so a test can look at the screen while a command is open | Check material properties only; reuse the EditMode `FakeTransport` | A property check would pass if the pipeline ignored them (the mutation run shows the render test fails then); `FakeTransport` lives in the EditMode assembly and answers at once | local |
| 9 | `PlacementFlow` is a plain class (`IDisposable`), not a `MonoBehaviour`: `GameRoot` creates it, passes `destroyCancellationToken` and disposes it in `OnDestroy`; the bar is the only new component | A component for the flow | Nothing in the flow needs `Update` or the Unity lifecycle, and a plain class is built by a test in one line | local |
| 10 | While a command is on its way the model ignores a new card or tile; the ground's tile marker and the menu may change, and a refusal puts both back in step (tile cleared, the menu shows the card again; the flow cancels if that card cannot be picked any more). A success clears everything | Let the pick change and cancel the flow; block the menu while sending | What was confirmed must stay what the ghost and the prompt say until the result; the player's taps are not lost into a hidden state | local |
| 11 | A card picked while no card was picked starts the flow: the sheet closes, a tile tapped earlier is forgotten; switching to another card keeps the tile and does not close the sheet; tapping the picked card again cancels | Keep an earlier tile | A stray tap on the ground before the card would otherwise jump straight to "confirm" | local |
| 12 | The bar is at the bottom right (the Build button is bottom left), 460 wide, Cancel and Place 64 high; `IsOverUi` of the menu and the bar are or-ed in `GameRoot`; `UiRoot` holds the two helpers every `UIDocument` screen needs (pick test, safe area) | Copy them into the bar; put the bar inside the menu's document | `BuildMenu`'s code was duplicated otherwise; a document of its own keeps each screen small (M0-45 decision 9) | local |
| 13 | A command that ends with no server answer to show, or an exception in the flow, fails with the code `CLIENT_COMMAND_FAILED` and its sentence, so the bar never stays on "Building…" | Leave the bar waiting | A stuck bar would block the card for good | local; M0-47 must give this code a message (follow-up) |
| 5 | The error line shows the error code and the server's sentence for now (`TILE_OCCUPIED: …`); the human message table is M0-47 | Write the message table here | M0-47 owns the code→message map and its completeness test; doing half of it here would be two tables | local; follow-up |
