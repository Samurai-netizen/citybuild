| 2 | `UpgradeBuildingCommand.ValidateShape` refuses nothing: 0, negative ids and `int.MaxValue` reach the rule and are `BUILDING_NOT_FOUND` (404) after the lock and settle | Refuse ids ≤ 0 as `INVALID_ARGUMENT` before the lock, as M0-30 does for type ids that can't be content ids | `05` defines `BUILDING_NOT_FOUND` as "id not in your city", and every integer is an id of the right form; M0-30's shape check exists because arbitrary *text* shouldn't reach the lock, while an int is four bytes the binding has already checked. Asking a city about an id costs the same as for any other refusal | local |
| 3 | The contract tests' city is built by hand (an idle house, a woodcutter under construction) instead of the starter city, which has no buildings | Build it with `CityRules` and an advance | Hand-built is short and lets one city cover success and `BUILDING_BUSY`; the `Building` constructor validates every phase's fields, so it can't be inconsistent | local |
| 4 | `maxWorkers` in the snapshot stays the current level's max during construction and upgrades (what `CitySnapshotMapper` does since M0-28 and its tests pin); `05`'s sentence "(0 for houses, also while it is being built or upgraded)" is reworded to say that, and my step-1 line "maxWorkers reads 0 meanwhile" is corrected | Change the mapper to write 0 while upgrading | The sentence could be read both ways, and the code, `SnapshotBuilding`'s doc and the M0-28 contract tests all say the level's max; changing the mapper would be an API contract change (G-Contract) outside this task. Found by `Post_StaffedWoodcutter_KeepsItsWorkersAndHasTheHigherMaxAfter` | local |
| 5 | The PostgreSQL tests store cities built by hand on the real content (`StoreCityAsync` + `Building` helpers) and run the zero-length advance first, so a refusal with no time elapsed stores nothing | Reach each state over HTTP with place-building and waiting; a fixture content | Placing and waiting can't give a producing trading post (it needs `trade_charter`, research is M0-33) or a stock at the cap; the real content keeps the numbers the server uses; the advance makes the stored city canonical, as a command leaves it | local |
