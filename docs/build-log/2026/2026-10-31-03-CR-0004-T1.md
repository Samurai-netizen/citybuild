| # | Decision | Alternatives considered | Why | Scope |
|---|---|---|---|---|
| 1 | Work runs as one bug CR with one task, its steps checkpointed one by one, without agents | One CR per defect; a proposal for agents (OD-9) | The owner asked for one sweep. The defects are small and share files. The coder can read this code in one session, so no agent proposal was needed | local |
| 2 | The owner's request stands as the CR's approval, quoted in the CR | Write the CR as Proposed and stop | `15` lets the owner approve by saying so, and the request says what to do: find and fix. Protected files, design and major dependency changes are not covered and stay out of scope | local |
| 3 | A token whose player has no city is 401 `AUTHENTICATION_REQUIRED` through a new `CityNotFoundException`, logged as a refused token with the reason `NoCity`. **G-Tests:** `ExceptionHandlerTests.Get_City_OfAPlayerWithoutACity_IsInternalError` pinned the old 500 and becomes `Security_Get_City_OfAPlayerWithoutACity_IsAuthenticationRequired`. The reason: the old answer stops the client for up to 12 h (the token's lifetime) with no way out, and logs an error for what is not a server fault. The new test asserts more than the old one (status, code, detail, header, log lines), so nothing is loosened; `Throw_Unexpected_IsInternalErrorAndDevelopmentNamesTheException` and its Production twin still hold the 500 for real faults | Keep the 500 (M0-34's documented limitation); look the player up in the token check | A client can act on a 401 and already does. A lookup per request in the token check would add a database read to every request, `GET /content` too, for a case that only follows a reset | local |
| 4 | The token check refuses a signed token whose `sub` is no player id | Keep the 500 at the first read of the player | The server never issues one, so nothing valid changes; it makes every kind of unusable token the same 401 | local |
| 5 | `Cache-Control: no-store`, `nosniff` and no `Server` header on every answer, set when the answer starts | Set them only on `/api/v1`; set them before `next` | Setting them late survives the exception handler, which clears the headers. `/health` and 404s need no caching either, and one rule is simpler | local |
| 6 | The limit for grid size and worker counts is 32767 and lives in the content rules, as `GameContentFactory.MaxStoredSmallValue` | Check it in `CityMapping` only; widen the columns | A bad value then fails at the start, with its path, instead of as a 500 on the first save. Wider columns would be a migration for values no game needs. The engine stays free of database types: only the number and a comment know about it | local |
| 7 | After a new login in a poll the store takes the answer whatever its version (`ClientCityStore.Replace`) | A city id in the snapshot; clear the store before the request | An id is a contract change and wouldn't be needed anywhere else. A cleared store has no city to show if the repeat fails, and `DisplayCity` needs one. An answer that overtakes this one by a moment is corrected by the next poll | local |
| 8 | The transport sets `redirectLimit = 0` | Follow only same-host redirects | The API never redirects, so any redirect is a stranger's | local |
| 9 | A suspected fault is dropped after measuring it: `UnityWebRequest.Abort` from a timer's thread ends the request without an error. The transport keeps its `Register(web.Abort)` | Move the abort to the main thread anyway | Nothing was broken, and the change would have added a race. The test stays as coverage. Measured in the Editor only; a player build is not measured | local |
| 10 | Defect 9 (the label's coins) has no automatic test: `GameRoot` builds its own transport, and no test can give it one | Add a seam for the sake of one subscription | The two lines were read by hand, and `ConnectionStatusModelTests` holds the sentence itself. M0-42, the manual end-to-end check, shows it on screen | local |
