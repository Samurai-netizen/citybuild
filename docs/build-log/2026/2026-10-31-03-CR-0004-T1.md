## Problems and surprises
- **A suspicion that measuring refuted.** The audit expected `UnityWebRequest.Abort` to fail on a timer's thread. A test against a socket that never answers passed on the unfixed code: 0.21 s, no main-thread error in the log. See decision 9. Measured in the Editor only.
- **A test pinned a defect.** `Get_City_OfAPlayerWithoutACity_IsInternalError` held the 500 of defect 1, and the Api module doc named it as a known limitation. See decision 3.
- **`dotnet test server/CityBuilder.slnx` without a filter hung for good on this Mac,** at 100 % CPU, after about 620 to 670 tests: 20 minutes and more until I killed it. CI and the docs run the two categories separately, which is why nobody had seen it. The stacks of the hung process (`dotnet-stack`, installed in the session's scratch folder, not in the repository) showed every stuck thread in `FileSystemWatcher.RunningInstance.Start` and in the configuration reload, and none in project code. The same run with `DOTNET_hostBuilder__reloadConfigOnChange=false` passed 739 of 739 in 15 s. See decision 11.
- **Self-review found one mistake of mine:** a patch had removed the doc comment of `StartupFlow.LoginAsync` (OD-12). Restored.

## Follow-ups
Findings the CR leaves out of scope. Each needs the owner.
- **Game design (G-Design): a permanent soft-lock.** Coins come only from the Trading Post, and nothing can be sold or demolished. A player who spends the 700 starting coins before the path to it is paid for (Trade Charter 150, Trading Post 200, and the wood chain: Woodcutter 80, Sawmill 150, 630 in all) can never earn another coin: fourteen Cottages at 50 are enough. The balance task M0-67 should look at it.
- **Protected files (G-Rules):** `ci.yml` has no top-level `permissions:` block, so its token has the repository's default rights (`docs-site.yml` has one); the actions are pinned by tag, not by commit; the pre-commit secret check looks only at file names, in a public repository (OD-7); the Unity tests don't run in CI.
- **Handbook packages (G-Dependency):** 28 advisories remain after the in-range fixes: 16 critical, 1 high, 8 moderate, 3 low. They come from three old packages: `tinypool` 1.1.1 (the critical chain), `serialize-javascript` 6.0.2 and `uuid` 8.3.2, through Docusaurus 3.10.2. `npm audit fix --force` would move Docusaurus back to 3.7.0, so it isn't the fix. The real one is `overrides` with major versions, or a newer Docusaurus. The exposure is low: they run at build time on this repository's own text, and the published site is static.
- **Deployment:** nothing in the server enforces HTTPS (`07` requires it in production); `AllowedHosts` is `*`; receipts and ledger rows grow without a cleanup job (`06` says "later").
- **Client, when views arrive (M0-44 onwards):** a command refused with `AUTHENTICATION_REQUIRED` should call `ConnectionMonitor.RequestPoll`, otherwise the new login waits for the next poll, up to 120 s. A failed start still doesn't retry (M0-41 decision 2): offline at launch means restarting the app.
- **Not verified:** defect 9 has no automatic test (decision 10); nothing was run on a device or in a player build.
