## Decisions
<!-- Every decision, when it is made, including small ones. Scope: local | project-wide (→ 12-decisions.md row) | architectural (→ ADR). -->
| # | Decision | Alternatives considered | Why | Scope |
|---|---|---|---|---|
| 1 | The helpers take `GameContent` (and the city) as well, unlike the spec's short signatures `PerHour(building, workers)` | Pass only the building | A recipe and the research-reduced labor come from the content and the city's completed research; a building alone can't give a rate | local |
| 2 | `IntegerMath.FloorDiv(dividend, divisor)` is added, same contract as `CeilDiv`; display helpers use it | A private `/` in the display code | `04` §9 and `simulation.md` allow division only through `IntegerMath`; flooring is right for display (never promises more) | local |
| 3 | Rates are in thousandths of an item per hour (`ItemRate.MilliPerHour`), rounded down; `PerHour` returns `ProductionRates` (inputs and outputs in recipe order) | Whole items per hour | A producer slower than 1 item/h, or an uneven cycle (3 workers on 40 labor), would round to 0 and make `SecondsUntilFull` null; thousandths keep the error under 0.001/h per building and let the UI print one decimal without floats | local |
| 4 | `PerHour` uses the city's current labor (completed research), previews 0..`MaxWorkers` of the building's current level in any phase, gives 0 for 0 workers, and throws for a house or workers out of range | Return null for houses | Programmer errors, like `CityQueries.EffectiveLabor`; the stepper only asks for valid counts | local |
| 5 | Display classes live in namespace `CityBuilder.Simulation.Display` (folder `Display/`), as static classes plus small result classes (`ItemRate`, `ProductionRates`) | One `DisplayHelpers` class | One public type per file and one topic per class (`14`) | local |
| 6 | `NetPerHour` counts a building when it has workers and is `Producing`, or `Idle` with `StallReason.Of` null; it uses the city's current labor and the assigned workers, also for a running cycle (the steady state, not the running cycle's own labor) | Count every building with workers; use `CycleLabor` for running cycles | A producer that can't start (missing input, full storage) doesn't make or use anything, which is what a player expects the rate to say; the steady state is the useful number | local |
| 7 | `SecondsUntilFull` = `CeilDiv((cap − stock) × 3.6·10⁶, netMilliPerHour)` against the effective cap; 0 when the stock is at or above the cap and the net rate is above 0; null when uncapped or net ≤ 0 | Subtract reserved output too | Spec says "when net rate > 0 (null otherwise)"; reserved output is an estimate detail (the doc says production stops slightly before the exact cap) | local |
